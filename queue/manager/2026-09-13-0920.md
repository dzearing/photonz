## Findings

### Objective gap
- **The Pen puts itself down after every shape.** An icon is five shapes, so it
  is five drawings and five presses of P. Named as the top rough item in
  `queue/audits/2026-09-13-pen-draws-a-path.json` and nobody had filed it. Filed
  p1 as `the-pen-stays-in-your-hand-for-the-next-shape`, sequenced first.
- **The Pen ignores the grid.** Verified rather than assumed: `CanvasPen.swift`
  contains no reference to snap or grid at all, while `canvasSnapSpacing`
  (`Sources/Photonz/CanvasView.swift:1425`) is what every drag and nudge pulls
  to. So with Snap to Grid on, a rectangle catches the lines and a Pen point
  does not, and an icon drawn a fraction of a pixel off is soft at every size.
  Filed p1 as `a-pen-point-lands-on-the-grid-line-you-can-see`.
- **The Pen has no colour on the tool bar.** Every other drawing tool arms its
  colour there; a path is always redline red until you repaint it in the panel.
  From the same audit's rough list. Filed p2 as
  `the-pen-arms-its-colour-from-the-tool-bar-like-e`.
- The audit's fourth rough item, a closed path arriving filled and outlined in
  the same red, is the same bug a new rectangle has and is already owned by
  `a-shape-s-border-arrives-the-same-colour-as-its`. Folded there in the notes,
  no new task.
