## Where the app stands
Focus is measure-redline. Everything the spec (`docs/design/next-measure.md`) promised is in the app behind Next-only flags, all default on: `next-measure-modes` (Distance, Size, Gap, Alignment in the tool button), `next-measure-align`, `next-measure-roles`, `next-measure-panel` (list, count pill, spec list, inspector export), `next-measure-center-snap`, `next-arrow-captions`, `next-tool-options`. No file in `Releases/Next/` is forked; every surface is shared code gated by a flag, which is what the spec asked for.
The user can try all of it today in Photonz Dev with release Next. Sixteen audits from 2026-08-23 and 2026-08-24 cover the measure work; arrow captions have no audit of their own.
Missing against the vision: the tool no longer says its mode in words (moved into a flyout on 2026-08-23), an alignment guide's row does not say what it checked, a two-point caliper still does not know what its feet landed on, spec export lives only in a panel menu, and capture has no window pick or loupe, which every competing capture tool has.

## Findings
### Objective gap
- Mode discoverability regressed when modes moved into the tool button (audit 2026-08-23-tool-mode-flyout, rough item 3); the hint chip only shows before the first measurement (`EditorState.showsMeasureHint`). Task `switching-measure-modes-says-which-mode-you-land`.
- Alignment guide row reads 'Alignment' with no count or reference edge (`MeasureSpecList.displayName`; audit 2026-08-23-alignment-guide rough items 3 and 4). No Name field in the inspector, rename is double-click only. Task `an-alignment-guide-s-row-says-what-it-checked-an`.
- A hand-drawn Distance caliper only protects its own line (audits size-readout-placement and measure-edge-readout, both said "filed as its own task"; it never was). Task `a-hand-drawn-caliper-keeps-its-number-off-the-th`.
- Arrow captions shipped (commit 7d8f6da) with one line in the big review and no audit. Task `arrow-captions-get-a-playtest-and-an-audit`.
- Size mode's two pinned misses (1 px border reads 2 px narrow, soft card outline 4 px narrow) need a new signal, not tuning. No action this pass; open thread.

### Competitors
- CleanShot X and Shottr both pick a window by hovering and clicking; Photonz has region and full screen only (`MenuBarMenu`, `EditorCommands` Capture menu). For a redliner that is the first step of every session. Task `capture-a-window-by-clicking-it`.
- Both also show a loupe with pixel coordinates while dragging; Photonz's freeze-frame overlay shows the selection size only. Task `a-loupe-with-pixel-coordinates-while-you-drag-a` (p3).
- Figma and Sketch inspect show element colors beside sizes; Photonz has no color sampler. Open thread, not filed: speculative until the user asks.

### Information architecture
- The Measure menu (`EditorCommands.swift:324`) has Measure Tool, Show All, Clear; Copy as Spec List exists only in the panel menu (`LayersPanel.swift:793`), and there is no way to copy one measurement. Task `copying-a-spec-list-or-one-measurement-is-a-menu`.
- The menu bar menu's Preferences… item is an empty closure (`MenuBarMenu`). Folded into task `the-menu-bar-menu-can-edit-the-last-capture-and`.
- Mode is reachable three ways (tool button flyout, I key cycling, Mode picker in the Measure Tool inspector). Deliberate per the flyout audit; no action.
- Tool letters live in one place (`Tool.shortcutKey`, PhotonzCore) and match the mocks since 2026-08-23. No action.

### Workflows
- Capture to editor: shift-command-4, drag, then the toast is the only fast path to Edit and it auto-fades; after that it is shift-command-H, find the card, Edit. No "edit last capture" command exists (grep in `Sources/Photonz`). Task `the-menu-bar-menu-can-edit-the-last-capture-and`.
- Measure: I, click, click, click per caliper; Size and Gap are one click. Hand off: shift-command-C copies the image; the text list needs the panel menu. Covered by the spec-list task above.
- Units: pixel scale is read from the capture's DPI on open (`EditorState.pixelScale(of:)`), so Logical vs Actual px works without a setting. No action.

### UI quality

- Perf budget: element detection at about 32 µs per move, caliper bake at 0.25 ms; nothing in the last week touched the composite path. No action.
