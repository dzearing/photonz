## Where the app stands
Focus is ui-building, sub-epic ui-components (component design end to end).
Against that focus the app today is a screenshot annotator: the picture always
starts as a capture, a file or a paste, the layer stack is flat, and nothing is
reusable. The three foundations a component needs are all missing. There is no
blank canvas to build on (EditorView.swift:402 offers Open a file, Capture a
rectangle and Paste an image; EditorState.swift:288 leaves a new window with no
document at all). There is no grouping: PhotonzDocument holds one flat
`layers: [Layer]` array and LayerContent has no group case (Layer.swift:324).
There is no library, no component, no instance anywhere in Sources.
What is genuinely there and useful for building UI: rectangles with a fill, a
corner radius and a border (AnnotationContent, plus the inspector rows at
LayersPanel.swift:1204 and 1328), text layers, undo through History.perform,
multi-select, and per layer opacity, blur and shadow. So a button can be drawn
today; it just cannot be started from nothing, sized to a number, kept together,
or reused.
The measure epic stays now and its remaining polish is legal work; five of its
tasks are still open. Every decision card is answered: none pending for the
first time since 2026-08-22.

## Findings
### Objective gap
- You cannot start a picture from nothing, so there is nowhere to build UI.
  Task `a-new-window-can-start-as-a-blank-canvas-you-can` (p1).
- The layer stack is flat, so a box and its label can never be one thing. That is
  the first rung of the component ladder: tasks `layers-can-hold-layers` (p1),
  `a-group-draws-as-one-thing`, `group-and-ungroup-what-you-selected`,
  `the-layers-list-shows-what-is-inside-a-group`, filed in that order with deps
  so they claim in sequence.
- Nothing is reusable. The mock defines the whole flow already (a component is a
  reusable layer tree with configurable properties; select, Make component,
  expose props, drop an instance, override one prop, reset). Spec task
  `the-component-model-is-written-down-before-it-is` (p1), then
  `make-a-component-out-of-what-you-drew-and-find-i` (p1, deps on it).
- Instances, overrides and variants are deliberately not filed yet: they are two
  rungs above what exists, and filing them now would be a queue nobody can
  claim. Next pass, once groups are real.

### Competitors
- Against Figma and Sketch, the gap that stops a first minute of work is not
  components, it is that you cannot type a size. Every design tool puts X, Y, W
  and H in the inspector; Photonz has no numeric geometry anywhere
  (LayersPanel.swift has sliders for style but no frame fields). Task
  `the-position-and-size-of-a-layer-can-be-typed-no` (p1).
- Second gap: aligning and evenly spacing a selection, which every tool has and
  Photonz has none of. Filed with a card, see Questions raised.

### Information architecture
- The mock's Library is a right dock panel group with scopes (Components,
  Styles, Media). Photonz has one Layers panel and no dock groups at all. Rather
  than invent a second panel system, the Make component task asks for the
  Library and the spec task has to say where it lives. No separate task; this is
  the seam to watch next pass.
- Nothing is homeless or duplicated in the current tool bar after this week's
  families work. No action.

### Workflows
- Walked on paper as a first-time user asked to build a settings row: step one
  (open a blank canvas) fails outright, step four (group the box and the label)
  fails, step five (line up the label in the box) has no help, step six (make it
  reusable) does not exist. Steps two and three (draw a rounded rectangle with a
  fill, put text on it) work today. Three of the four stops are now filed; the
  fourth is on a card.
- The scripted walk of this flow, the equivalent of the redline walk, cannot be
  written until groups exist. Open thread for next pass.
