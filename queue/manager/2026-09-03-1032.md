# Manager pass 2026-09-03 10:32

Fifth pass. The last one was 17 hours ago and 80 finished tasks ago: the whole
component ladder (A through E of `docs/design/ui-building.md`) landed overnight,
the end to end scenario has an audit, and at 10:19 this morning the user answered
the auto layout card, promoted `ui-layout` to now, and the first stack and grid
work landed with it. So this pass is not reading a plan, it is reading a working
feature and asking what it still cannot do.

## Where the app stands
Focus is `ui-building`, with `ui-components` and `ui-layout` both staged now.
What a person can try today in Next, all on by default: blank canvas, typed
position and size, groups, frames, the Library shelf, Make Component, copies that
follow their original, knobs and overrides, named colors, five starter
components, align and space, placement rules on resize, and as of this morning
`next-auto-layout`, a group that arranges its own contents as a stack or a grid.
What is missing is the second half of "fits its contents": a stack is always
exactly as big as what is inside it, and a text box never re-measures itself, so
a longer label still overhangs the shape behind it. And the right hand panel
still speaks for one layer in every section except Color, Position & Size and
Arrange. No decision cards were pending when this pass began; one is now.

## Findings

### Objective gap
- Auto layout stops one rung short: a stack cannot be told its own size, so
  "this menu is 320 wide and its rows fill it" is impossible off a screen. The
  follow-up was already filed this morning; raised to p1 and put first
  (`a-stack-can-be-a-fixed-size-and-its-rows-fill-it`).
- Nothing re-measures text. `TextRasterizer.naturalSize` wraps correctly and is
  used when text is committed or restyled, but a width change and a wording
  override both skip it (`Document.setInstanceOverride`,
  `ComponentProperties.swift:498`, writes the string and never touches the
  frame). That is the "nothing fits its contents" line six audits wrote
  yesterday, still true. Task `a-label-grows-to-fit-what-it-says` (p1).
- Per side padding and a hug or fill along the flow axis are named as not built
  in the auto layout audit. The fixed size task covers the fill half; per side
  padding is an open thread rather than a near twin task.

### Competitors
- Against Figma, Sketch and Photoshop, the gesture missing from the first minute
  of building UI is Option drag to leave a copy. `duplicate` does not appear
  anywhere in `CanvasView.swift`; the only way to copy is the menu, which lands
  the copy exactly on top and leaves you to drag it off. Photoshop binds this to
  its move tool, so it is parity, not invention, and needs no card. Task
  `option-dragging-a-layer-leaves-a-copy-behind` (p1).
- The column overlay every design tool draws behind a screen (twelve columns, a
  gutter, a margin) does not exist. It is new chrome nobody asked for and a
  cousin of the guides turned down on 2 July, so it is a card, not a task. See
  Questions raised.

### Information architecture
- The panel still answers for one layer. `LayersPanel.swift:157` gates Effects,
  Shadow, the shape settings, the text settings, the layout rows and the
  component rows behind `if let layer = selectedLayer`, which is empty over a
  multi selection. Proof in a real capture from this morning:
  `queue/audits/2026-09-03-color-one-home-2-two-layers.png`, two rectangles
  picked, five sections on screen and no way to round both their corners. Tasks
  `fade-blur-corners-and-shadow-reach-everything-yo` (p1) and
  `the-shape-and-text-settings-reach-everything-you` (p2, deps on it).
- Color has one home now except one: the border color is still a swatch inside
  Effects and still opens the system color window rather than the app's own
  picker, so it cannot wear a saved color or be set over a selection. Task
  `a-border-color-sits-with-the-other-colors` (p2).

### Workflows
- Walked building a settings row from nothing: every step that failed at the
  last pass now works. Blank canvas, draw, group, stack, make a component, drop
  a copy, rename it on the canvas. The two stops left are the two filed at p1:
  copying a row means a menu trip, and retyping a label longer cuts it off.
- Capture, measure and redline were re-walked end to end by the step 9 audit
  yesterday and are untouched. No task.

### UI quality
- No probe build this pass, on purpose: nine audits from this morning carry real
  window captures with the Screen Recording grant, which is better evidence than
  a fresh render and costs the loop nothing. Read
  `2026-09-03-auto-layout-2.png` and `2026-09-03-color-one-home-2-two-layers.png`
  side by side: the Layout section reads cleanly, and the only jarring control in
  either is the black color pill in the Effects Border row, which is the drift
  the border color task removes.
- The Color section moves about 175 points down the panel between one layer and
  two, because Arrange appears and Position & Size gains a line. Noted by its own
  audit as a question about what the dock leads with. Open thread, not a task.

### Architecture
- Force unwraps in `PhotonzCore` and `PhotonzRender`: still zero. No new
  `@preconcurrency`. `Releases/Next/` still holds only `NextExperience.swift`, so
  everything overnight reached Next by being shared and the porting rule has not
  been bent.
- `EditorState.swift` is now 269 KB, up about 90 KB in a day, and
  `CanvasView.swift` is 198 KB. Nothing is broken by it and no task is filed yet:
  the split is only worth doing behind a feature that needs it, and the next two
  p1 tasks both add to these files. If the pass after this one finds a third,
  file the extraction then and name the feature it de-risks.
- The pure core boundary held through the component work: measurement is injected
  into `PhotonzCore` through closures (`StarterComponents.layer(kind, measure:)`)
  rather than by importing CoreText, and the text task says to keep doing that.

### Repeated code
- No new duplication found. The one seam to watch is the mixed value reading over
  a selection: Color built one in `ColorStyleSelection.swift`, and the two
  multi selection tasks filed today say to reuse it rather than write a second,
  with the maths in the core and not in the view.
