# Manager pass 2026-09-13 07:14

Tenth pass, four days after the ninth. In between the loop shipped Separate into
Layers in six slices, a tutorials framework with six tracks, and about five
hundred commits. The user answered all seven open decision cards this morning and
asked, in the same sitting, for a Pen that draws polygons with hard edges and
bezier curves "to build elaborate SVG icons". `icon-svg` was promoted to `now`
for it and three Pen tasks were filed.

This pass is deliberately small. The queue came in with sixty five ready tasks,
not two, so the job was not to fill it. It was to ask whether the top of it
actually finishes what the user asked for. It does not, and that is the finding
the rest of this report hangs on.

## Where the app stands

Focus is `ui-building`, but the top of the queue is `icon-vector`: a path model,
the Pen, and reshaping a drawn path, in that order.

What a person can try in Next today: components with versions, knobs, overrides
and sharing; colour, text and effect styles; auto layout with stacks, grids,
wrapping, gaps and hug; measure in three modes with a spec list to copy out;
lenses that blur or pixelate what is under them; blend modes; Separate into
Layers and Turn into Text; and a Help menu of guided tutorials in six tracks.

What is missing is the other half of the sentence the user typed. The three Pen
tasks end with a path you can draw and reshape. There is no way to get it out of
the app: `grep -ril svg Sources/` returns nothing, and `ImageCodec.Format`
(`Sources/PhotonzRender/ImageCodec.swift:10`) is png, jpeg and heic. There is
also nowhere to draw an icon: `Sources/PhotonzCore/Frames.swift:28` offers
Desktop, Laptop, Tablet, Phone and Square, and the smallest is a thousand pixels
across.

## Findings

### Objective gap
- **You will be able to draw an SVG icon and not be able to save one.** Export is
  three bitmap formats and a 1x/2x scale (`ExportDialog.swift:43`). Filed p1 as
  `an-icon-you-drew-comes-out-as-an-svg-file`, sequenced right behind the Pen,
  with `icon-export` promoted to `now` to hold it.
- **There is nowhere to draw an icon.** No frame preset under a thousand pixels,
  and no way to see a 24 pixel icon at 24 pixels while you draw it, which is the
  one thing that makes icon work different from shape work. Filed p2 as
  `a-new-frame-can-be-an-icon-size-and-an-icon-is-s`, with `icon-grid` promoted
  to `now`. Keylines and snapping deliberately left out of that slice.
- **Booleans are in the epic's own title and were not filed.** `icon-vector` reads
  "booleans, strokes, gradient paint", the mocks have `draw-boolean.html`, and the
  Pen set's own notes call booleans the next thing once a path exists. Nobody
  filed them. `grep -in 'union|subtract|intersect' Sources/PhotonzCore/` finds
  only CGRect and Set. Filed p2 as `two-shapes-become-one-join-them-cut-one-out-keep`.
- **Gradient paint, the third word in that title, is already done.**
  `Sources/PhotonzCore/Paint.swift` and `PhotonzRender/GradientPainter.swift`
  exist, and the path foundation task already requires a path to take one. No
  action, recorded so nobody re-files it.

### Competitors
- Against Illustrator, Figma and Sketch, the gap that matters for the focus is
  not the Pen, which is queued, it is that **a rectangle stays a rectangle for
  ever**. Nobody starts an icon with the Pen; they drop a circle and then want to
  pull one side of it. Filed p2 as `a-rectangle-or-an-ellipse-you-drew-becomes-a-pat`.
  This is also what stops the Pen being a separate world you have to commit to
  from the first click.
- **Line icons cannot be drawn at all.** `Layer.swift:122` has strokeWidth and
  strokePosition and nothing for ends or corners, so every stroke is chopped flat.
  The visual identity of a modern icon set is its cap and join. Filed p2 as
  `a-drawn-line-has-round-ends-and-round-corners-or`, as two settings beside the
  outline controls that already exist rather than a new section.
- Deliberately not filed: an icon grid with keylines, pixel-fitting, and a stroke
  that scales with the shape. All real, all further down the same epic, and the
  queue does not need them yet.

### Information architecture
- The four new tasks all land on surfaces that already exist: the Layer menu and
  the layers row menu for conversion and booleans, the outline controls for caps
  and joins, the New Frame list for icon sizes, the Export dialog for SVG. One new
  visible surface between them, the icon preview strip, which is why that task
  carries the mock references rather than a free hand.
- The canvas still has no context menu anywhere in the app, which the digest
  correctly called a foundation question rather than a focus gap. Unchanged, no
  action.

### Workflows
- Walked drawing an icon as a first-time user, on today's app plus the three
  queued Pen tasks: open a document, and stop. There is no icon-sized frame, so
  you draw on a 1440x1024 desktop frame or a bare canvas. Draw the shape. Now get
  it out: PNG at 1x or 2x. That flow has two holes in it and both are now filed.
- Walked handing a redline over: unchanged from the last pass and still whole,
  now with a lens for covering a name, which closed the gap the ninth pass filed.

### Architecture
- Force unwraps in `PhotonzCore` and `PhotonzRender`: still zero. No new
  `@preconcurrency`. `Releases/Next/` still holds only `NextExperience.swift`, so
  nothing has forked and the porting rule has not been bent once.
- The 5,017 line `LayersPanel.swift` the ninth pass filed is gone: the largest app
  file is now `EditorView.swift` at 2,657 and the largest core file is
  `Layer.swift` at 1,841. The split landed and nothing grew back into it.
- One thing worth saying out loud for the SVG task: the document model is
  top-left origin and so is SVG, so the flip `DocumentRenderer` owns must not be
  applied by the writer. Written into that task's notes because getting it wrong
  produces an upside-down file that reads as a rendering bug.

### Repeated code

- The four icon tasks were written to converge rather than fork: booleans and

## Staging changes

both with the reason written into their notes. `icon-vector` was already `now`
and holds the Pen set. Nothing was sent back: `ui-building`, `ui-components`,
`ui-layout` and `measure-redline` all still hold real open work.

One thing left alone on purpose. `unmanned-loop` and `design-system` are staged
`next` and hold fifteen open tasks between them, which the staging rule says
should not happen. Five of those are playtest harness faults that stop features
being verified, which is exactly the exception the rule carves out, and the other
ten are p3 doc scrubs sitting at the bottom of the queue where they cost nothing.
Churning them would destroy real work to satisfy a field. Recorded rather than
acted on.
