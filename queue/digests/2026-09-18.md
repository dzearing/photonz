## Reflections

**Nine cards waiting is the bottleneck now, not the building.** Nine of the
twenty one open tasks are stopped on a question only you can answer, including
every task at p1. The loop is not short of work, but it is short of the work
that matters most: two of the three p1s are the focus and the near focus
(a component copy showing authoring controls it cannot use, and whether the app
should have modes at all). Everything the loop can do without you it is doing at
about thirty tasks a day.

**The locked screen is costing about eight and a half hours of loop time a day.**
Ten partial sweeps ran in the window, each about 51 minutes, each covering the
same 249 lock-safe walks, because the once-per-commit floor never binds when a
commit lands every hour. Meanwhile 277 walks have been unchecked for four days.
That measurement is now logged on
`a-hundred-and-fifteen-walks-fail-on-code-that-pa` as evidence for the card
asking whether the loop should keep the Mac awake. It is the single highest
value answer available today.

**A clean result is a result, and the loop was throwing them away.** Found
during triage and filed as
`a-clean-sweep-leaves-the-standing-task-saying-wh`: a sweep that finds nothing
failing never writes anything down, so the standing task the dashboard reads
keeps whatever the last broken sweep wrote, under a heading promising it is
rewritten every time. Right now it names four walks the sweep passed fifteen
minutes ago. The general lesson is worth keeping: every reporting path in the
loop was built on the failing case, and the passing case was assumed to need no
words.

**An idea worth queueing later, not now.** The reading of a page's labels does
not always agree with itself: over two runs of the same 142 pictures one run
disagreed with the other about a row. That is recorded honestly in
[the audit](../audits/2026-09-17-what-a-reading-found-is-saved.json) and it is
the real argument for writing the answer into the file, which is what shipped.
It did not earn a task because the feature that shipped makes it stop mattering
for any file saved from today on. If a reading ever disagrees with a saved one,
that is the day to file it.

## Design review

**Is the IA sound? One rule bent, and it bent four separate times in one day.**
The panel column has no rule for what it owes a section when what the sections
want does not fit the window, and four unrelated pieces of work hit that in the
same 24 hours: the Library shelf being carried below the fold after a drop
([shelf-stays-put](../audits/2026-09-17-shelf-stays-put.json)), tiles below the
shelf's fold being reported as a missing component
([starter-shelf](../audits/2026-09-17-starter-shelf.json)), the Layers list
showing five rows of a 24 layer document while Effects and Motion say "Nothing
yet" and hold the bottom third of the dock
([separate-into-layers](../audits/2026-09-18-separate-into-layers.json)), and
Appearance sitting below the fold again
(`appearance-is-below-the-fold-again-because-the-p`). That last task already
owns the rule; its acceptance requires UX-PATTERNS section 3 to gain it.

**Missing guidance: a section the panel has squeezed should say it has been
squeezed, and only one of them does.** The Library fades its cut edge so three
tiles showing out of five read as three of five. The layers list bounds itself
the same way and ends on a clean cut, so five rows of twenty four read as the
whole document. One treatment, two behaviours, and the second one makes a person
wrong about what their document contains. Folded into
`appearance-is-below-the-fold-again-because-the-p` as an acceptance addition
rather than filed separately, because that task's rule already has to answer
"what the column owes the section it pushes" and this is the same question for a
section it shortens.

**Nothing was hand-rolled that the design system should own this cycle.** The
Experiments window grouping used existing section chrome and deliberately added
no new control; the shelf fade already existed as a treatment and the finding is
that it is not applied consistently, which is a conformance gap rather than a
missing component.

**Recurring UX issue: numbered names where the app already knows a word.** The
separation names every run of text after the words in it, and then names every
non-text piece Box 1 through Box 10, so a card, a button, a switch and a text
field all arrive with the same name and a number. Half the list is searchable
and half is not, on the app's primary surface. Filed against the focus epic as
`a-separated-switch-says-what-it-is-instead-of-bo`.

**Rule scrub queued.** Four places say the full walk sweep is 322 walks and
about 52 minutes. There are 526 walks and a full run now measures nearer a
hundred minutes, against a two hour stop that was set when a sweep was under an
hour. That number is the whole reason a task runner is forbidden to start a
sweep, and the first full sweep after the screen is unlocked is what finds out
whether the stop still has room. Filed as
`the-sweep-s-size-is-the-size-it-really-is-in-the` covering CLAUDE.md,
`queue/README.md`, `queue/sweep/README.md` and the comments in
`queue/bin/sweep.sh`.

**Judging the focus feature as a user.** Separate into Layers is close to good
and two things are in the way, both of which the runner's own evaluate list
names. First, the numbered boxes above. Second, the pill says ten boxes on a
pane where a person would count four, and the list you would use to check that
shows five rows out of twenty four. So the feature does more work than it did
yesterday and is harder to believe, because neither the count nor the list lets
you verify it. Both findings are now carried: the naming as its own task, the
list height on the panel task.
