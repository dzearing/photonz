## Design review

**Is the IA sound?** Two bends, both worth naming. First, a new transient surface appeared on the canvas: the mode hint pill and the Copied pill share one "canvas notice" slot at bottom centre, reserved while Measure is in hand, which is why the legend can never use the bottom corners on a narrow window (audit `measure-hint-lines`, rough 2). It works, but it is a third transient family beside the capture toast and the overlay choreography, and the pattern doc's surface taxonomy (UX-PATTERNS section 3) does not name it. Second, the app has two command surfaces, the menu bar and the panel menus, and no rule that they mirror each other. Three separate tasks in 24 hours were that drift: the capture menus naming one command two ways (`capture-menu-names`), Copy as Spec List living only in a panel menu (`spec-export-menu`), and Hide All missing from the Measure menu (the pending hide-all task). The mock's own answer, a Properties panel menu for Copy Measurement, bent to the native menu bar instead (`spec-export-menu`, rough 4). Both bends are rule gaps, not bad builds; the scrubs are queued below.

**Are we missing components or guidance?** Two things got built three times. Pill placement: arrow captions, measurement readouts and the roles legend each have their own scorer, and every placement fix today landed in exactly one of them (manager pass 02:40, Repeated code; commit fcf2775 added the third). Queued: [every-pill-on-the-canvas-finds-its-spot-through] (p3, waits on the two placement decisions). Scripted playtests: three audits each rebuilt a throwaway harness to drive the probe editor with synthetic events and render it offscreen; the runner already filed [a-reusable-scripted-playtest-harness-for-the-pro], retagged today as loop tooling. One thing was rightly shared on the first try: the hint pill and the Copied pill use one notice chip.

**What UX issues keep recurring?**

- **Callouts landing on their subject.** Nine tasks and three open cards: caliper subjects, gap under a label, boxed-in caliper, readout travel, guide chip sliding, legend edge slot, hint covering the legend, caption pill off the picture, dragged arrow losing its caption. The pattern is one rule (D14, never cover the subject) implemented separately per surface, which is the extraction above.
- **Two names or two homes for one command.** Four tasks: capture names, hide-all, spec list menu, edit last capture. See the IA bend.
- **Two words for one number.** The loupe says pt, the editor says px for the same logical size (`redline-walk` evaluate 5), and the spec list header reported device pixels above logical rows until the walk fixed it. The loupe task moved to p2 today.
- **Nothing verified live.** All 21 audits say screen recording is denied to the loop; the window capture shadow (`window-capture-shadow`, rough 1) is the one feature whose output the loop could not even predict. The grant card is open.
- **Counts that are not what a person would count.** Three alignment audits (`alignment-guide-row` rough 3, `guide-edge-chip` rough 3, `guide-buttons-aligned` rough 2): the guide counts ink runs, so a split label counts twice and stacked elements once.
