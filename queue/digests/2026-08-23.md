## Reflections

- **Queued: [go-loop-surfaces-runner-failures-instead-of-spin] (p1).** This is the important one. A failing runner is currently indistinguishable from a working one, because nothing writes the failure anywhere the dashboard reads. Three fixes: record non-zero runner exits with their last error line into `status.json`, back off and park a task after N consecutive failures instead of hot-retrying, and give the Summary hero an unhealthy state. A system that runs unattended has exactly one obligation, which is to tell you when it has stopped, and today it failed that obligation for thirteen hours.
- **Queued: [canvas-selection-frames-come-from-one-shared-hel] (p2).** See the design review; this is the day's clearest "built five times, own it once" signal.
- **A model fallback is worth considering, not yet queued.** The loop could fall back to a cheaper model when the preferred one is unavailable rather than stalling. Holding off deliberately: silently degrading model quality on an unattended loop may be worse than stopping loudly, and that question should be settled after failures are visible, not before.
- **The retry storm cost more than time.** 3,959 claim-and-reset cycles wrote 3,959 history events, which is now most of `history.jsonl` and skews the Data tab's charts. Whatever fix lands should also collapse repeated failures into one event with a count.
- **On the product side**, Next Measure now has enough surface that the next honest step is using it end to end on a real screenshot rather than adding another feature to it. A "redline a real capture start to finish" dogfood task would find more than another spec section will.

## Design review

**Is the IA sound?** Yes, and it got stronger rather than bending. Three changes this cycle removed vocabulary instead of adding it: the workspace switcher is gone from the shell entirely, Assets collapsed into Systems so the Library has one honest set of four scopes, and blank-slate entry became one shared template instead of a per-surface invention. No surface this cycle needed chrome outside the UX-PATTERNS vocabulary. The one addition, a Measurements dock group, is a panel group in the one dock, which is exactly the sanctioned way to add capability.

**Are we missing components or guidance?** The cycle answered this well on its own: `seg.multi` was extracted when icon-draw-wt needed toggle chips, and the missing-primitives batch promoted specimen cards, preset chips, and the full selection-handle set into shared components. One gap remains and it is the recurring issue below.

**What UX issues keep recurring?** One pattern dominated, appearing in **five separate tasks**: a page's copy promises a selection while the canvas draws no ring. It was fixed by hand on `walk`, `composites`, `img-retouch-wt`, `icon-gradient-wt`, and all six video walkthroughs, and the fix was the same markup every time (`.selwrap` wrapping `.sel-ring`, four `.handle`s, and a `.mtag`). Five identical hand-fixes is the definition of something the system should own, hence the queued extraction task. Second, smaller pattern: segmented chips clipping their labels inside dock panels, which surfaced twice and was fixed structurally with natural-width columns, then confirmed non-reproducing in a 90-page sweep.

**Do the documented rules need a scrub?** They were scrubbed as the work landed, which is the right order: `UX-PATTERNS.md` section 1 lost the workspace switcher, D2 was rewritten for the Systems scope, and `AGENTS.md` and `PRODUCT-MODEL.md` were updated alongside. No stale rule found this cycle. The one guidance gap is the selection-frame rule: the pattern doc says selection must be shown consistently in three places, but nothing enforces it, which is why five pages drifted. The queued task includes an audit gate so the rule can fail a build rather than wait for a reviewer.
