Across everything
Design order (not build order): Primitives → API → UI. A scriptable command model can't be vague, so defining it forces a shared vocabulary. That serialized model is the design system — the thing that keeps every scenario (UI, image, video) predictable and lets Claude drive all of it.
Primitives → API → UI

Primitives

Five shared building blocks. Everything is expressed in these.

Paint · solid/gradient/image/noise
Effect stack · glow/shadow/blur
Layer · raster/vector/text/group
Type · ramp, weight, tracking
Tokens · spacing/radius/color
→

API

Primitives serialized into one IPC command surface. Claude and the app both speak it.

// same commands the UI calls
create_layer({
 kind:"instance", of:"Button",
 fill:style("Brand/gradient"),
 effects:[style("Card glow")]
})
→

UI

Every panel & tool is a thin client over the API. Nothing the UI does, Claude can't.

🎨 Inspector → edit fill/effects
🧩 Design system → styles & components
✦ Claude → drive by prompt

Tier 1 Tokens

Raw values: color, spacing, radius, type scale. The atoms everything references.

Tier 2 Styles

Named Paint / Effect / Type. Edit "Brand gradient" once → every use updates.

Tier 3 Components

Reusable layer trees you instance and re-paint with any Style. Figma-style, Photonz-native.

The idea

Five primitives, plus a design-system tier on top: Tokens → Styles → Components. This is how creation stays consistent instead of sprawling.

Reuse, like Figma

A Style is a named primitive; a Component is a reusable, paintable layer tree. Both are first-class in the API, so Claude composes with them too.

The point

Whichever wins — or ship all three — they call the exact same commands the UI does, and reuse the same components & styles. Automation is the API made visible, not a bolt-on.

Model-agnostic

The API is the contract, so the model is pluggable: a local Qwen (MLX/LM Studio) as the private, offline default; a frontier model via MCP when you want more. The schema keeps even a small local model safe — only valid, undoable commands.
