# UX audit rescan · 2026-08-23 · clusters A-G over all 88 pages

Fresh scan for the conform-pass task (queue id
`finish-the-mock-conform-pass-across-all-pages`). Ten disjoint audit passes
(one per page family) against `shared/ux-audit-agent.md`, judged against the
CURRENT scalable-dock shell target, plus a full browser measurement sweep
(`shared/audit-sweep.js`) at 1280x900 over every page.

**Headline: the July/August component rebuild landed.** Clusters B, C, D and E
are clean on almost every app page: every editor sits in `.win.tall.cq` >
`.edit.lean` > `.cnv` + `.tbar` > `.pdock` of `.dgrp` groups > `.drail`, with

selection routed to Properties. What remains is a long tail of F (bespoke

items, and a copy tail.

## Fixed centrally in this pass

- **Dock segs no longer ellipsize.** `.pdock/.dgrp-b/.cpick` segs used equal
  `1fr` columns; any label a few px longer than its siblings rendered with a
  permanent `…` ("Textured", "Lower third", "Columns" on 14+ pages) while
  staying under the collapse threshold. The dock default is now the
  natural-width geometry the scopeseg/multi variants already used
  (`shared/components/segmented.css`).
- **Collapse-to-menu now fires on any real overflow** (`segmented.js`): the
  old one-ellipsis tolerance left labels visibly clipped forever
  (draw-boolean, redline).
- **`audit-sweep.js` measured invisible things.** It counted the `.seg-plate`
  and the `.seg-alt` menu trigger as chips and measured `visibility:hidden`
  chips of collapsed segs, and its equal-width assertion predates the
  natural-width dock default. Now it checks only visible chip buttons for
  truncation.
- Copy: hard-rule violations fixed in foundations (capitalized "Agent" x4,
  ascii `→` in `.farrow`), ideas ("AI alt-text"), img-masking (visible API
  string `type: "ai"` -> `"agent"`), comp-agent (em dashes in product
  strings), app-shell (em dash in redline card).
- **Sweep result after fixes: 88/88 pages clean** (no overflow, no zero-size
  canvas, no truncated chips, no clipped panel toolbars).
