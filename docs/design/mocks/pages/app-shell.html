Click a header to collapse a group to its header. Drag the divider to resize the group above it. Each body has its own bounded height and its own scrollbar, so a 60-layer stack scrolls inside Layers and never pushes Effects or Library off screen. Stack as many groups as scope needs, the shell does not change shape.

The idea

Lean by default, canvas first. A floating tool bar holds tools, color, and zoom. One right dock holds stacked panel groups. Everything else is a rail, a splitter, or an overlay. New capability is a new group, never new chrome, so the app can grow into UI design, components, and richer video and still feel like the same app.

Direction

The three moves that make it scale are collapse, resize, and scroll. Each group has its own bounded height and its own scroller, which is why one long list can never crowd its siblings. When the window narrows, the same markup rails the dock, turns it into an overlay, and folds the overflow tools into a more menu.

Open question

The dock currently remembers one size per document. Should a workspace lens also carry its own dock layout, so switching to Video restores the panel set you last used there, or does that break the promise that a lens only re-arranges chrome around the same document?
