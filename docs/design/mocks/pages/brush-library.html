The idea

A brush library is not its own window. It is the Library panel group with its scope set to Brushes, sitting in the same dock as Layers and Properties. Picking a tile sets the active brush, drives Properties, and repaints the sample stroke on the canvas, exactly the way picking a media tile behaves. Designing one brush lives in the brush editor.

Direction

Because a brush is data, the library is a filtered list of objects. Import a .brush file, make one from a selection, or start fresh, and it drops into Custom next to the built in sets. When you want room to browse, the same content opens as a slide-down overlay instead of widening the dock.

Open question

Should tiles preview against the current Paint and canvas so a brush shows how it will actually read in this document, and should Brushes be a first class Library scope alongside Media, Styles, and Systems, or a filter inside Media?
