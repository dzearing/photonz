01

The clip

A clip is a layer with an in and an out, so it carries the same selection language as anything else on the canvas and adds only what time requires: trim edges that appear on hover, a speed badge when it is retimed, and key marks (.kfm) for the frames where something about it changes. The marks are read-only here on purpose — the timeline answers when, and what belongs to the clip detail pane.

Position in percent of the document's duration, so the same clip survives a zoom. Draw a keyframe you can drag on the clip. Two places to edit one key is two places to get it wrong.

API .clip in a .lane.abs · .kfm marks · .edge.l/.r trim handles · .speed badge.

02

The edit point

A transition belongs to the join, not to either clip — it changes both sides — so the thing you select to add one is the cut itself. Without this primitive a page has no way to express "the join is selected", and the only demo left is splitting one clip and dissolving it into itself, which is not an edit anyone would make.

Invisible at rest, a hairline on hover, accent when selected. Give it width. A cut has no duration until a transition is on it.

API .editpt · .editpt.sel. Zero-width, centred on the seam.

03

The overlap, and what pays for it

This is the one idea the whole video language is built on. A transition overlaps two clips, so it never occupies a slot of its own and putting one on never moves a frame of anything. What it spends is spare media — frames past a clip's in or out point that were recorded but are not being read. So the band draws over the clips and the spare draws outside them: one shows the cost, the other shows what is available to pay it.

That is also why a cross dissolve can be impossible where a dip to black is not. Run out of spare and the editor has to say so, rather than silently shortening someone's shot.

A runs forward along the top, B runs back along the bottom — ownership is positional, so it needs no legend. Put the transition in a track of its own. It would imply a transition has a place in the stack, and that adding one can push things around.

API .xband (.sel, .blk for a dip) with .gr.l/.r grips · .xspare.a/.b with a .lb duration.

04

The two ways out, and the proof

Left, the counter-example. A dip is a fade-out and a fade-in that each live inside their own clip's time. No overlap, no spare spent, nothing moves — which is exactly why it is always available. Drawn as an outline rather than a fill, because the tail, the black and the head underneath all have to stay readable.

Right, the proof. Expanding a cut puts the two clips on their own rows, where an overlap stops being a metaphor: it is literally two clips playing at the same time. Anyone who does not believe the band can open this and count the frames.

Keep the expanded rows on the same time axis as the collapsed one. Explain the overlap in a tooltip. Show it.

API .xfade.in/.out · .xband.blk · .track.xrow with .xused and .xboth.

05

Picking a transition

A transition is picked with the same tile grammar as a component, a style or a brush — one library idiom, four scopes — so nothing here is a bespoke picker. What is video-specific is the second line: each tile states what it would cost in spare media, and a tile the cut cannot afford is disabled rather than hidden. Hiding it would leave you wondering where cross dissolve went; disabling it tells you to trim.

State the cost before the choice, not after it fails. Invent a transition picker. It is .libtile with a thumbnail.

API .libtile.tt · thumbnails .th-diss/.th-dip/.th-slide/.th-push/.th-morph/.th-cut · [disabled] when there is not enough spare.

06

The dock, collapsed

The timeline is the biggest thing between you and a full-height preview, so it collapses — to one row, mirroring the panel dock's rail. The row reports the selection rather than the panel's name, because the reason you collapsed it was to look at the canvas, and the question you then have is "what am I still editing".

Write data-tl-summary and let the component pick it up. Author the × or the rail. dock.js injects both into any .win > .timeline.

API .timeline[data-tl="open|closed"] · .tl-close · .tlrail · data-tl-summary. See UX-PATTERNS D9.

Why these are components

They look like decoration, so they get re-invented per page — the overlap band lived on exactly one page, scoped to its id, even though it carries the single most video-specific idea in the product. A primitive that encodes a rule has to be somewhere an author can find it, or the rule gets re-litigated every time.

The one rule to keep

A transition is not a clip. It has no slot, it moves nothing, and it is paid for in spare media. Every visual decision here follows from that: the band draws on top, the spare draws outside, the dip is an outline, and the expanded rows exist so the claim can be checked.

Open question

Spare media is drawn only while the cut is selected. Should it be permanently visible at low contrast, so you can see which cuts have room before you pick one — or is that a timeline covered in dashes?
