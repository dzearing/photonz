Ask · the agent surface

· Surfaces & primitives Component library

The surface behind Ask, and the primitives inside it. One launcher opens one conversation, and that conversation is also the ⌘K command palette — so the sentence you type and the command you run land in the same place. This page specs what is in that surface: the .run card that reports what the agent did, its four states, how the changes are grouped and selected, and what happens when you move the whole thing into the dock so you can watch the canvas while you steer.

The unit is the run, not the message. A transcript of prose is the wrong receipt for an editor: nobody wants to re-read a paragraph to learn that the headline went 36 → 44. What you want is the list of changes, grouped by the layer that changed, each one clickable.

01

Anatomy of a run

A card per turn of work: .run → .run-h, .run-b of .run-grps, .run-f. The rule that makes it useful is that a step is a value change, not a sentence. "Made the headline bigger" is unverifiable; 36 → 44 is a number you can disagree with.

Show before → after for every step, including the skipped ones. Summarise a run in prose and hide the changes behind a disclosure.

API a run is a list of the same commands the UI issues: layer.set("headline","fontSize",44). There is no agent-only command, which is why the receipt can be rendered at all.

02

Four states

Idle, busy, done, and the one everybody forgets: steering. The card's own state lives on .run[data-state]; the surface's state is just which of these is on screen. The transitions matter more than the states — a step never un-happens, so busy → done adds ticks rather than re-rendering the list, and the card does not resize under your cursor.

Keep the composer live at every state, including busy. Replace a running list with a finished one. Fill it in.

Rule the busy state is only legal if it can be stopped. Every busy run has a Stop, and stopping keeps every step that already landed rather than rolling back the lot.

03

Grouped by target, selected as one

A run of eleven edits across three layers is three things, not eleven. Group by the layer that changed, order the groups to match the layer tree, and the transcript reads top-to-bottom the same way the Layers panel does. Then make every row a selector: clicking a step selects its layer, ⌘ or ⇧ extends, and that is the canvas selection — not a second highlight that means something else.

Order groups by the layer tree, so two panels agree. Invent a transcript-only highlight. One selection per document.

Undo a run is one history entry by default — "make the card pop" is one thing you did. Per-step revert (the ⤺ on hover) peels one change off before you move on, which is the correction people actually want: "all of that, but not the shadow".

04

Dock it to steer it

Same conversation, two hosts. The chat moves rather than being duplicated — one node, so there is no second transcript to keep in step. The compact form is driven by @container convo, not by the window width and not by a .docked variant class: a variant would let the two drift apart, and a window query would measure the wrong box (the window is the same width in both pictures).

Drop ornament as it narrows: the meter, the count, the cost. Truncate the value. "Corner ra…" is guessable; 4 vs 14 is not.

Auto-collapse one expanded group per intent. While you are steering, that is the intent, so the dock's other groups fold to their headers — marked .auto-collapsed, re-expanded when the conversation leaves, and never overriding a collapse the user made themselves. Each keeps its title and count, and Layers keeps a reason, because it is the one the run card actually replaces.

The calls this page makes

and what they cost
QuestionAnswerWhy, and what it gives up
Prose or a list?Both — one sentence, then the run cardThe sentence carries intent, the card carries fact. Prose alone is unverifiable; a bare list reads as a machine log.
Group by what?By target layer, in layer-tree orderMatches how you would answer ("leave the headline alone"). Costs you the true chronology, which nobody has ever asked for.
How is a change selected?Clicking it selects the layerOne selection model in the app. Costs the ability to "select a step" as a distinct thing — deliberately, since two selections is the confusing outcome.
One undo or many?One per run, plus per-step revert"Make the card pop" is one thing you did. The per-step ⤺ handles "all of that but not the shadow" without spraying seven entries into History.
Can you type while it works?Always. Enter queues, ⇧Enter interruptsDisabling the composer while busy is the single most common mistake in this class of UI. Costs a little ambiguity, which the two-key hint pays for.
Float or dock?Float by default, dock on demandMost asks are one sentence and want the biggest target. Supervising a long run wants the canvas visible, so the same chat moves into the dock.
Docked width?The dock's own 268px, compact under 340No new width for the agent; it is a panel group like any other. Layers auto-collapses to pay for the vertical space.

In the API every step is a command the UI can also issue, and the run is the transaction that wraps them: history.perform(run). That is what makes the receipt renderable at all — if the agent had a private path into the document there would be nothing to list, and nothing to undo as one step.
