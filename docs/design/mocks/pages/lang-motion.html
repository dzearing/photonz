01

Anatomy

A motion is a duration paired with an easing. Short moves use dur-1, panels and toasts dur-3. Standard for most transitions, decelerate for things entering, spring only for a deliberate settle.

Pick from these six values, nothing between.Reach for a 500ms ease-in-out because it "feels smooth".

API motion.duration = "dur-2" · motion.easing = "standard". Tokens resolve to the same CSS variables the UI uses.

What animates

A short list, on purpose. Only discrete state changes animate: something opened, closed, appeared, was picked, or moved. Continuous values (dragging a slider, typing, panning) track the input directly and are never tweened.

03

Variants

Three shapes cover everything. Enter arrives on decelerate so it lands softly. Exit is quicker and plainer so leaving never feels sluggish. Move can spring, but only to settle an object into a new place.

Make exit faster than enter.Spring an enter, or bounce an exit.

API motion.variant = "enter" is picked from the transition's direction; you rarely set it by hand.

Idle
at rest, no motion pending
Trigger
state flips: open, select, add
Animating

Settled
final state, fully interactive

Reduced motion jumps straight from Trigger to Settled: same start, same end, zero duration in between.

04

States

A motion has a lifecycle, and it is always interruptible. Trigger the same control mid-animation and it retargets from where it is; it never queues or fights itself.

Let a new input take over the current animation.Block the UI while something is still moving.

API a command resolves once the target state is set, not when the animation ends, so an agent never waits on visuals.

Live examples

Three you meet constantly. The button lifts on hover, presses on click. The section grows its own height on dur-3. The toast drops in, holds, and auto-fades so you never dismiss it.

The reduced-motion rule. Every demo on this page is wrapped so it works with motion off. When prefers-reduced-motion: reduce is set, or the switch at the top is on, transitions and keyframes collapse to near-instant: the chevron still rotates, the toast still appears and clears, the section still opens. Nothing that conveys meaning is lost, only the in-between frames. We never gate content or feedback behind an animation, so removing motion removes nothing but the drift.

07

Responsive & compact

In a small or compact window there is less distance to cover, so durations step down one token and long "move" animations may simplify to a plain fade. The vocabulary stays the same; only the amount of travel shrinks.

API compact windows set ui.density = "compact", which nudges motion to the shorter tokens automatically.

The idea

Motion earns its place only when it explains a change. Three durations and three easings are enough to make the whole app feel alive without a single thing bouncing or spinning for attention.

A direction

Bake the tokens into the render layer so a command like toast() or section.collapse() carries its own motion, and honoring motion.reduced is automatic rather than something each feature remembers.

Open question

Should spring exist at all? It is the one easing that can feel playful. Do we keep it for a couple of deliberate settles, or drop to two easings and stay strictly functional?
