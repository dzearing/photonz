Menus & dialogs

· Component library Component library

Four surfaces that float over live content, ordered by how much they interrupt you: a menu (pick one thing, then it is gone), a popover (work in it, click away to dismiss), a sheet (a decision about this document, attached to its window), an alert (something irreversible). The rule the whole page rests on: reach for the least interrupting one that works, and a modal almost never is.

01

The interruption ladder

Pick the lowest rung that works. Most things people reach for a modal for are really a popover, and most of the rest are a toast with an undo. A modal is a promise that the answer cannot wait, and in an editor that promise is almost always false.

Prefer a sheet to an alert. A sheet blocks one document, not the app. Confirm something you could simply undo. Do it and offer undo.

API menu.open() · popover.open(anchor) · sheet.ask(document, …) · alert.ask(…). The rung is chosen by the call, not by styling.

02

The menu item

A menu is the command API made browsable, so an item is a view over a command and takes everything from it: label, icon, shortcut, enabled state, destructiveness. Nothing about an item is authored twice, which is why the menu can never drift from the toolbar.

Show the shortcut on every item that has one. This is where people learn them. Hide a command when it is unavailable. Disable it and say why.

API the item is command. A menu is commands.filter(…), which is also what the agent's / list shows.

03

The sheet, in place

Hinged to the title bar of the window it belongs to, over a scrim that dims that window only. Button order is platform law: confirm on the right, cancel to its left, and a third option pushed to the far left with real space. .dlg-f lays that out, so a page cannot get it wrong by accident.

Name the document in the question. "Save changes?" to what? Put the primary on the left because it reads first in English.

API sheet.ask(doc, {title, options:["Don't Save","Cancel","Save"]}). The order in the array is the order on screen, left to right.

Read the Blocks column top to bottom: four of six block nothing at all, and that ratio is the design. Escape closes every rung, and on the two that block, Escape means Cancel, never the destructive option. Compact windows: a popover anchored to a control that no longer has room becomes a sheet from the bottom edge rather than shrinking, because a squeezed popover is worse than a relocated one.

The idea

An editor's job is to stay out of the way, so the library makes the non-blocking surfaces the easy ones to reach for and the blocking ones deliberately awkward. Most confirmations are really an action plus an undo.

A direction

Because menus are generated from commands, the same list powers the agent's / filter. A menu could show what an agent just ran, in place, so the two ways of driving the app teach each other.

Open question

Sheets are correct on macOS and awkward for a menu-bar app with no front window. When a capture finishes and no document is open, does the question become an alert, a notification, or does it just wait?
