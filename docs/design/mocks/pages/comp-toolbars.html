Three bars, and each one has a job the other two must not take. The title bar says what the document is. The floating tool strip holds the tools that change what your pointer does. A contextual bar holds actions for what is currently selected. Keeping them separate is what stops the top of the window turning into a junk drawer. 01

The floating tool strip

A capsule that floats over the canvas rather than docking above it, so it costs no permanent height and the document stays the whole window. Inside, groups are separated by a hairline and ordered by what they act on: the pointer, then the paint, then the view. That order never changes between workspaces, so muscle memory survives switching from image to video.

Group by what a control acts on, and keep the order. Put a document action (Export, Share) in the tool strip.

API run("tool.pen") sets the current tool; tool.current reads it. The strip is a view over the tool registry, so adding a tool does not mean editing a toolbar.

Identity only: lights, document name, dimensions, and the one affordance that opens the agent. No actions live here. The moment a Share button lands in the title bar, everything else follows it.

Appears because something is selected, and its contents depend on what. It leads with the selection's name so you always know what the buttons will act on, and ends in an overflow.

02

Three bars, three jobs

The split is about what the controls act on. Title bar: the document, and only its identity. Tool strip: the pointer. Contextual bar: the selection. A control that acts on the selection must never live in a bar that is always there, or it will be disabled most of the time.

Name the selection at the head of the contextual bar. Keep a permanently disabled button in a permanent bar.

API the contextual bar is generated from selection.actions, so a new node type brings its own toolbar rather than someone laying one out.

03

The tool button

A tool is a mode, not an action, so its selected state is persistent and loud: an accent fill with a glow in its own colour, not a subtle tint. The corner notch means "press and hold for variants" — the marquee holds ellipse, the pen holds curvature. One extra pixel of language, and it removes a whole row of buttons.

Give every tool a one-key shortcut and put it in the tooltip. Use a tool button for something that runs and returns.

API run("tool.marquee", {shape:"ellipse"}). The variant is an option on the same command, not a second tool.

One rule underneath all of it: drop the label before the control, and the control before the group. What never happens is a bar wrapping to a second row, because a two-row toolbar changes the canvas height and every layout below it moves. Everything that folds into an overflow menu keeps its shortcut, so the fast path survives a narrow window even when the button does not.

The idea

The tool strip floats. That one decision is why the canvas can be the entire window: chrome that costs no permanent space can be generous without making the document smaller.

A direction

Because the strip is a view over the tool registry, it could reorder itself per document type and remember the change, with a reset always one click away. A video document would surface blade and speed where an image document surfaces brush and crop.

Open question

A floating bar over the canvas always covers something. Do we let it fade out during a drag and come back on release, or keep it solid and let people move it to any edge?
