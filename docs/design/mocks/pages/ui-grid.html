Grids and constraints in the API

A grid is a property, a constraint is a property
// the layout grid and every constraint are just fields on the model
frame.grid = { cols: 12, gutter: 16, margin: 24 }
bar.constraints = { x: "stretch", y: "top" }  // full-width top bar
share.constraints = { x: "right", y: "top" }   // hugs the right edge

The same command runs whether you drag the frame, script it, or ask the agent. You set the rule once and the frame keeps the layout correct at every size, on UI, a photo, or a video title card.

The idea

A layout grid gives a frame shared structure (columns, rows, or a mesh with a gutter and margin), and constraints tell each element how to respond when the frame resizes. Pin to an edge, center, or stretch across both. The design stays aligned instead of drifting.

A direction

Constraints and auto-layout are two halves of the same story: auto-layout packs children along an axis, constraints pin them to a frame. Snap constraints to grid columns so a pinned edge lands on a real gridline, not a raw pixel.

Open question

Should the grid bind to spacing tokens so the whole file restacks when the scale changes, and should breakpoints be first-class, so a frame can carry a different grid and constraint set per size?
