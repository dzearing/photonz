A pro editor is mostly numbers in a narrow panel, so the number field is the most important control in the app and the one the platform gives us the least help with. The text field, the select and the three toggles are the supporting cast, and the rule for choosing between the toggles is written down here rather than left to taste.

01

The number field

Four behaviours make it feel professional, and all four have to be there: drag the label sideways to change the value, type arithmetic and units, arrow keys step (with shift for 10x), and spinners appear on hover so forty of these in a panel stay quiet. Right-aligned tabular figures so a column of numbers is readable as a column.

Ship the scrub gesture. It is what people reach for first. Round the display and keep a different value underneath.

API node.frame.w = 320. The field parses the expression, the command takes the number. One undo entry per commit, not per keystroke.

02

Number states

Two states here exist nowhere else in the system and both matter. Mixed is what a multi-selection shows: the word, not a made-up average, and typing replaces it for every selected object. Bound means the value comes from a token or a constraint, so editing it either breaks the link or asks first. Unavailable is the narrow one: a field that will take the keyboard again once you fix what is in the way. A number that is never yours to type is not a dimmed field at all, it is the readout in 03.

Show the token name when a value is bound, not the resolved number. Show 0 for a mixed selection. Zero is a value someone might keep.

API selection.frame.w returns mixed for a heterogeneous selection; assigning to it applies to all.

03

The number you cannot type

No box. The rounded bezel is this system's promise that the keyboard lands there, so a number the app worked out for you does not wear one: it is plain text in the same slot, secondary strength, monospaced digits. Both looks were built and photographed side by side and the plain one won. Clicking it answers in the line under the section, straight away, because a click that does nothing is the first thing a person learns about a panel that ignores them.

Leave the value empty and take the en dash the component supplies. Dim a field to say a number is not yours. It looks like an input and reads as broken.

API selection.frame.w still answers; what changes is .editable, and the panel picks the control from that. Never in the tab order: Tab moves between the numbers you can type.

04

Text fields

A rounded rectangle, not a capsule, and that is deliberate: a capsule says "press me", a well says "put something here". The round ends would also waste the first and last 8px of a 92px field and stop a column of values from lining up. Monospace whenever the content is compared down a column: hex, sizes, timecode.

Commit on blur and on Return; Escape reverts. Validate on every keystroke. Validate when they stop typing.

API node.name = "Hero card". Search is find("hero") and returns nodes, so an agent uses the same index the field does.

05

Select

For 5 or more exclusive options, or fewer when space is tight. Below that use a .seg. The closed state always shows the current value in full, never a placeholder, and the open menu ticks the current item rather than highlighting it, because highlight means "keyboard cursor is here".

Show a preview swatch when the option has a visual result. Use a select for two options. That is a segmented control.

API layer.blend = "multiply". The option list is enum("blend"), so the menu and the completion an agent sees are the same list.

06

Switch, check, radio

The choice between them is about when it takes effect and how many there are, never about which looks better in the layout. Geometry follows the round-inside-round rule: the knob in a capsule track is a circle, the checkbox is a rounded square so it cannot be mistaken for a switch at a glance.

Put the switch on the right of its label, in a .setrow. Use a switch for something that only applies when you press Apply.

API a switch writes immediately (view.snap = true); a checkbox collects into the command's options (run("file.export", {hidden:true})).

07

In context

A real 264px inspector column. Every row is label left, control right, on the same grid, with a 9px uppercase caption over each run. That rhythm is what lets you scan forty values without reading any of them, and it is why the row containers (.setrow, .slrow, .numgrid) ship with the components rather than being written per panel.

Let controls fill the right column to a common width. Mix 24px and 32px controls in one panel. Pick the density once.

API the whole column is generated from the selected node's schema, so a new property gets the right control without anyone laying out a panel.

Compact windows keep the control and drop the label into a tooltip; a .numgrid falls from 2-up to 1-up before any field shrinks below 60px, because a number field narrower than that cannot show four digits and a unit. Every field commits on blur and on Return, and reverts on Escape — one rule, no per-panel exceptions, so you can always back out of a mistake the same way.

The idea

The number field is the app. Getting scrub, arithmetic, units, stepping and the mixed state right in one control is worth more than any other component on this page, because it appears hundreds of times per session.

A direction

Because values can be bound to tokens, a field could show its source on hover: the token, the constraint, or the component property driving it, with one click to jump there. The panel becomes a way to navigate the document, not just edit it.

Open question

Unit parsing is a rabbit hole. Do we support inches, points and percent everywhere, or only where the document has a physical size? Percent of what is ambiguous the moment a layer is inside a group.
