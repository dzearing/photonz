  1. 1

    Ask, or press ⌘K

    the title bar, on the right

    the agent chat opens over the canvas, and it is also the command palette: type / and it lists the ordinary commands you can run. The agent is not a separate window: it is one more thing you can run from here.

  2. 2

    Ask, with the goal typed: Make a pricing section on brand

    the agent chat's composer

    the Agent group opens in the dock with a readable plan: six named commands, the same ones the tool bar and the panels call. Nothing has run yet, and you can see the model it will use.

  3. 3

    Run plan

    the Agent group, under the command list

    the section builds on the canvas, command by command. Layers fills with a real Pricing frame and three Card instances, each plan line checks off, and the purple rings show that these are linked instances, not flattened art.

  4. 4

    the Library group header

    the right dock, bottom group

    Library opens at scope Components and Card now reads 3 instances. That is the proof the agent reused your component instead of drawing a look-alike.

  5. 5

    Styles

    the Library scope switch

    the same panel, a different scope: Brand / gradient and Price / 28 are the named paint and type it used. Re-paint the system later and everything it built re-resolves with the rest of your work.

  6. 6

    the Studio card

    the canvas, with the Select tool

    the ordinary three-place selection: the ring on the canvas, Card · Studio in Layers, and Properties. What the agent made is a live layer tree, so from here it edits exactly like anything you drew.

  7. 7

    send, with the request typed in the Agent group

    the Agent group, at the bottom of the panel

    two named commands come back, not a redraw: the CTA grows and repaints with Accent / 500. You can read both before deciding, and either one undoes on its own.

  8. 8

    the CTA · Fill change row

    the Agent group, in Last change

    the selection jumps to that exact layer on the canvas and Properties shows the bound style. The agent hands the work back as ordinary layers, which is the whole point: the design stays yours.

The idea

Everything the UI does is one command, so the agent needs no private API and no private window. It is reached from the command surface, it appears as a panel group like Layers or Library, and what it produces is ordinary layers bound to your components and styles.

A direction

Because the command schema is the contract, the model is pluggable: a local Qwen (MLX) as the private, offline default, or a frontier model over MCP. Same commands either way, and only valid, undoable steps.

Open question

How much plan should you see before it runs: the whole list up front, or commands that stream and draw as they execute with one undo for the batch? And should a published system be able to forbid raw values outright, so the agent cannot invent a color even if asked?
