Design language

· how the app itself behaves · frame, panels, overlays, motion

This is the app's own language: the chrome, panels, overlays, and motion that hold a document. It is separate from the Design system, which styles the content you make. Every pattern below is a live specimen built from the same tokens, with one rule for when to reach for it. Each is also addressable: a docked panel, a collapsed section, an open palette are all one command away, so an agent drives the exact same surface you do.

The frame

Traffic lights, then document identity (the name plus its context, 1200 × 630 or 0:18), then the workspace lens, then the document actions. One document per window, so the window is the document. Never a lesson title, a feature name or a shortcut.

Keep identity centered and actions right.Put zoom, a mode name or a tool in the title bar.

API doc.name drives the title. Compact: the size drops out, the lens folds away, the frame never grows a second row. Full pattern.

Command surface & tool bar

The native macOS menu bar is the real command surface, so the app draws only a compact ⋯ button plus the ⌘K palette. Tools never live in a fixed row: they float in the bottom tool bar over the canvas, with the color pair and zoom.

Fold low-priority tools into the tool bar's ⋯.Draw a fake menu bar, or a permanent options row.

API tool.active = "select" · every palette row is one named command. Compact: overflow tools collapse, then the zoom slider drops. Full pattern.

The one dock

There is one dock, on the right, holding stacked panel groups: Layers, Properties, Effects, Library. Each group collapses to its header and scrolls inside its own bounded height, so a 60-layer stack never pushes Library off screen. New capability is a new group, never new chrome.

Give a long list its own --gh bound and scroller.Add a left dock, or tear a panel off into a floating window.

API panel.open("library") · section("Effects").collapsed = true. Compact: the dock becomes a rail plus an on-demand overlay. Full pattern.

Splitters

A .splitter.v sits between the canvas and the dock; a .splitter.h sits between stacked groups. Visible grip at rest, accent on hover and drag, keyboard-resizable, bounded by data-min and data-max. Sizes persist for the session.

Show the grip at rest so it reads as draggable.Let a group shrink past its min and lose its header.

API dock.width = 320 is persisted. Compact: the vertical splitter goes away entirely and the dock rails. Full pattern.

Overlays

Command palette (⌘K) and menus are transient: one action, dismiss on choice or Esc. A tooltip is hover-only. A toast auto-fades. A sheet is modal: it blocks until answered.

Give every menu item its real shortcut.Put a destructive step behind a toast.

API every menu item is a named command run("effect.shadow"). Compact: the palette becomes the primary way in.

Selection & canvas

A selected object gets an accent ring plus corner handles and a live measure tag. Drag empty canvas for a marquee; a thin line is a snapping hint as edges align.

Show the size tag while resizing, not at rest.Draw handles that overlap the object's own controls.

API select(["Button"]) · a component instance rings in purple. Compact: handles grow their hit area on touch.

Elevation & glass

A single ladder keeps depth legible: stage < window < panel < popover < menu. Only floating, transient surfaces get glass and the big shadow.

Raise a surface only when it floats above content.Give a docked panel a drop shadow.

API elevation is implicit in the surface role, not a free style. Compact: shadows soften so stacked glass stays readable.

09

Density & spacing

One 4pt scale, nothing between the steps. 16 pads cards, 12 pads rows, 24 insets a window. Compact mode drops one step, never invents a new value.

Round every gap to the nearest scale step.Ship a 7 or 15px one-off to "make it fit".

API density is a document preference ui.density = "compact". Small windows adopt compact automatically.

10

Motion

Motion is short and functional: it explains a state change, then gets out of the way. Under 300ms, plain easing, no springs.

Animate the thing that actually changed.Loop or auto-play decoration.

API honors prefers-reduced-motion: transitions collapse to instant, results stay identical.

Color & states

Accent means "you can act". Purple always means component. Green/amber/red are reserved for good, warn, and critical. Every control carries the same four states.

Show a visible focus ring for keyboard users.Use red for anything but a real problem.

API a disabled command reports why it is unavailable, so an agent gets the reason too.

Keyboard

Shortcuts follow Photoshop where they can, so muscle memory carries over. Single letters pick tools, ⌘ runs commands. A feature that would collide moves, not the familiar key.

Print the shortcut next to its command everywhere.Reassign a shortcut people already know.

API every shortcut maps to one named command run("tool.text") · see it in use.

The idea

A shared language makes the whole app predictable. Learn the frame, panels, overlays, and motion once and every surface, from a photo to a video timeline, behaves the same way.

A direction

Today this lives in shared/photonz-ds.css. In the real app it would be codified under docs/design/ as the app-shell spec, each pattern paired with the command that drives it so the agent and the UI stay in lockstep.

Open question

How much layout should users rearrange? Free-floating panels are powerful but easy to wreck. Do we ship a couple of trusted presets, or a fully open dock with one-key "reset layout"?
