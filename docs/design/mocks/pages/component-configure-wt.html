  1. 1

    the Setting row group

    Layers, in the right dock

    the group you drew by hand is selected in three places at once: the ring and handles on the canvas, the row in Layers, and Properties. Right now it is three ordinary layers, nothing reusable.

  2. 2

    Make component

    the Layers group header

    the layer tree becomes the main component Setting. The canvas shows the component ring and badge, Layers marks the row, Properties gains a Component section, and the component lands in Library at scope Components.

  3. 3

    Add property

    Properties, in the Component section

    a picker opens listing the layers inside this component and the kind of knob each one would make. It stays open while you pick more than one.

  4. 4

    Toggle · on / off

    the property picker

    a boolean prop named enabled joins the Component section. The toggle layer is no longer fixed: every instance can set it and stay linked.

  5. 5

    Control · toggle / segmented / stepper

    the same picker, still open

    a variant prop named control appears, listing the three shapes this row can take. A variant swaps what is already in the tree, so an instance can never drift into something the main does not contain.

  6. 6

    the Toggle child row

    Layers, nested under Setting row

    selection moves inside the component, and Properties follows it: this layer's Fill is a literal color, which is exactly what a design system cannot re-paint.

  7. 7

    Styles

    the Library scope switch

    the same Library panel, a different scope. These are the named paints the active system publishes, the ones a component should bind to instead of hex.

  8. 8

    Accent / 500

    Library, scope Styles

    the toggle track stops carrying a hex value and starts carrying a name. Properties now reads Accent / 500, so changing that style once re-paints this component everywhere it appears.

  9. 9

    Comp

    the Library scope switch

    back to the components scope, where Setting is now listed with its two props. This is the same panel you have used for media and styles, which is the whole point of one Library with scopes.

  10. 10

    Setting onto the canvas

    Library, scope Components

    a linked instance lands under the main and takes the selection. Properties swaps to Instance props: the two knobs you exposed, plus the label, and nothing else.

  11. 11

    Segmented on the control row

    Properties, in Instance props

    the instance re-renders as a segmented row while the main stays a toggle. The link is intact, so editing the main still flows through, and the override is only the one prop you set.

The idea

A component is a reusable layer tree with configurable properties. Nothing in this flow is a component editor: it is the ordinary Layers group, the ordinary Properties group, and the ordinary Library group, which is why the same moves work on a photo or a video track.

A direction

Because styling is bound to Styles rather than baked in, applying a different system re-paints every instance at once. The same Setting renders as a toggle, a segmented control, or a stepper from one variant prop.

Open question

Every step is one API call (component.fromSelection, component.addProp, layer.bindStyle, instance.props.control), so an agent can author components too. Should a variant prop be allowed to add or remove layers in the tree, or only swap what is already there?
