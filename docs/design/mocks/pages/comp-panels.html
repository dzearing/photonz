Panels, panes & rows

· Component library Component library

Everything that holds content at the side of the canvas. The vocabulary is deliberately small: a dock holds panel groups, a group holds sections, and a section holds rows. Four nouns, and every panel in the app is built from them, which is why a new feature never needs new chrome. The docking, resizing and tear-off behaviour lives on Design language · Panels; this page is the parts.

01

Anatomy

Dock > group > section > row, and every level collapses. That is what lets one 280px column hold Layers, Properties and Library at once without becoming a scroll marathon: you close what you are not using and the rest expands into the space.

Give every collapsible thing a visible affordance in its header. Invent a fifth level. If it needs one, it is a separate group.

API panel.dock("right") · group.collapsed = true · section.collapsed = true. State is per document, so a layout follows the file.

Hidden and locked dim the whole row, including its name, because a dimmed row is the fastest way to read "this is not participating" down a list of forty.

02

Rows

The row is the most repeated element in the app, so it is the one that has to survive density. 24px tall, one line, icon then name then trailing state, and the name truncates rather than wrapping. Trailing controls appear on hover except when they are on, because a locked layer must show its lock without being hovered.

Keep trailing state visible when it is active, hidden when it is not. Let a long name wrap. A two-line row breaks the scan.

API node.hidden = true · node.locked = true. The row is a view over the node, so a row and the canvas can never disagree.

LIBRARY Collapsed group

The header stays. A collapsed group you cannot see is a group you will not find again.

Panel manager .dockmgr

A sticky footer on any dock with two or more groups, built from that dock's own groups so no page authors it and none can drift.

03

Managing the dock

A dock that can hold five groups needs an obvious way to choose which ones are shown, or people close a panel and never find it again. The manager is generated from the dock's contents, so it is always complete and always correct.

Leave the header when a group collapses. Let a panel disappear with no way back except a menu three levels deep.

API dock.panels lists them; panel.visible = false hides one. The manager is a view over that list.

Compact windows: the dock collapses to the rail rather than shrinking, because a 160px inspector cannot show a label and a control on one line. Below that it becomes an overlay over the canvas, which costs zero width and is the only way a phone-width window keeps a usable canvas. The layout is per document, so the panel arrangement you set up for a video file is still there when you reopen it.

The idea

Four nouns, and every level collapses. A vocabulary this small means a new feature adds a group, never a new kind of chrome, which is the only way a dock survives fifty releases.

A direction

Because groups are data, a document could carry a named layout: "Retouch" opens Layers plus Adjustments, "Handoff" opens Measure plus Export. Switching is one command, and the layout travels with the file.

Open question

Per-document layout is right for a designer with one big file and wrong for someone opening forty screenshots a day. Do we make it opt-in per document, or infer it from how long the document stays open?
