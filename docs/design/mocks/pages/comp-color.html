Color picker

· Component library Component library

The largest custom component in the app, and the one with the strongest rule attached: there is one color picker and every color slot opens it. No second gradient editor, no separate palette window, no "advanced" mode. Fill, stroke, text, shadow, a gradient stop, the foreground swatch in the tool bar: same popover, same state, re-anchored. The full picking scenario is on Color · picking; this page is the component spec.

01

Anatomy

Eight regions, no modes. Everything the picker can do is on screen at once, which is what makes it feel like a tool rather than a dialog. The vertical order is deliberate: what you are painting, what kind of paint, the coarse pick, the precise pick, then the shortcuts to a neighbouring color.

Keep the picker one surface. Every "advanced" panel is a failure. Open a second window for gradients. That is the split we exist to avoid.

API layer.fill = color("#7C4DFF") · color.shade(-2) one step darker · color.style("Brand/500") once it has a name.

Fill Stroke Gradient The swatch trigger .cpick-btn

One trigger shape for every slot: a swatch plus the value. It shows a gradient as a gradient, so the slot tells you what kind of paint it holds before you open anything.

The tool-bar pair .swpair

Foreground and background, with a swap. The one place a swatch is not labelled, because the canvas is the label. Both open the same picker.

02

Triggers

Two shapes, and both open the same popover anchored to whatever you clicked. The picker keeps its recents and its shades across slots, so moving from Fill to Stroke does not reset what you were working from. That continuity is most of why the one-picker rule pays off.

Anchor the popover to the trigger and keep its state. Add a second, smaller picker for "quick" colors. There is one.

API picker.open({slot:"stroke", anchor:el}). The slot name is what the header shows.

Same picker, gradient paint

Choosing Linear adds the ramp and the stop rows in place. The field, channels and swatches below now edit the selected stop. Nothing moved, nothing opened.

Stop 1 POSITION 1% The stop callout

A card riding the ramp over the selected stop, at .elev-3: the one surface allowed to sit on a popover. Its beak is a single SVG path, because a glass card with a 1px stroke would show a dimple where a box beak met its border.

03

Gradients are paint, not a mode

The type switch changes what kind of paint you are editing and leaves the editor where it was. Every other tool treats a gradient as a separate dialog, and the cost of that is real: you lose the shades, the recents, and the contrast readout the moment you need them most.

Let the stop rows appear in place under the ramp. Ship a "gradient editor". The word itself is the mistake.

API paint.type = "linear" · paint.stops[1].color = "#B14DFF" · paint.angle = 135.

The system picker is a color chooser; this is a paint editor, and the gap is not closeable by restyling. Compact windows: the popover keeps its width and becomes a sheet anchored to the bottom of the window rather than shrinking, because a 180px SV field is not pickable. Reduced motion removes the open scale and keeps the fade.

The idea

One picker, every slot. The rule sounds like tidiness and is actually a feature: because the surface never changes, its memory never resets, and the shades you were working from are still there when you move to the next thing you are painting.

A direction

The "In document" scope already knows every color in the file. It could offer to merge near-duplicates into one style right there, which is the cleanup nobody does because it currently means auditing a document by hand.

Open question

The contrast readout compares against whatever sits behind the painted object. With a gradient behind a gradient there is no single pair to score. Do we sample the worst case, the average, or drop the readout when it cannot be honest?
