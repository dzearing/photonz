The Layers pane

· surfaces & primitives Panes & panels

Everything in a Photonz document is a layer: a photo, a shape, an arrow, a text block, an adjustment, a whole UI component, a video clip. So the Layers pane is not a list of things you drew, it is the document itself, made addressable. It is one pane in the one panel (see Panes & panels), and it does four jobs: select, structure, reorder, and hide. Everything below is one of those four.

01

Anatomy

One tree, one column, no tabs. The pane shows the whole document at every level of nesting and never splits itself into "layers" and "objects" and "assets". If it is in the document it is a row here, and if it is a row here you can select it, move it, group it, and hide it.

Keep one tree that mirrors the composite order. Add a second list for a new kind of content.

02

The row

Six slots, in the same order, on every row
Step 1 · box

Every slot is always there

A slot with nothing in it stays empty rather than letting the row reflow. That is what makes a column of forty rows scannable: the eyes line up, the names start at the same x, and the glyphs sit in one column you can read straight down.

Indent means parent

One indent step per level of nesting, and no other meaning is ever encoded in indentation. Groups nest without limit, so the step stops at six levels and deeper rows say their own depth instead. The nesting is unbounded; only the whitespace is capped.

The name is the label

Double-click, or press ↩, to rename in place. A layer you never named shows a derived name in a lighter weight ("Rectangle", "IMG_4021"), so a real name is visibly different from a default one.

The point of the sameness: once every kind of content is a row with the same six slots, a person learns the pane once and a new capability costs no new UI. A video clip and a rectangle behave identically here because in the document model they are the same kind of thing.

04

Selection

One selection, shown in three places at once: the ring on the canvas, the highlighted row here, and the contents of Properties. Select in any of the three and the other two follow, which is what makes the pane a way of reaching a layer rather than a separate inventory of them.

Multi-select shows a ring around the combined bounds, every matching row highlighted, and only the properties they share. Nothing is hidden that they have in common, and nothing is offered that would silently apply to just one of them.

Scroll the selected row into view when the canvas selects it. Let a canvas selection leave the pane scrolled somewhere else.

1Yes, and there is no limit. A group is a layer and a group holds layers, so a group holds groups, all the way down. Nothing in the model counts levels, so nothing in the model can run out of them.
2⌘G on a selection that already contains a group nests it. Grouping is the same command at every level, which is what keeps deep structure cheap to build rather than something you plan in advance.
3Effects compose down the chain. Opacity on Onboarding multiplies opacity on Screen 2 multiplies opacity on Callouts. A mask on any level clips everything under it. That is the reason to nest at all.
4The indent step stops, the nesting does not. Past six levels the rows stop moving right and the depth is spelled out on the row instead, because a tree that spends more width on indentation than on names has stopped being readable.
5Every command is depth-blind. Select, drag, hide, lock and ungroup take a layer, and a group at level nine is a layer. There is no separate vocabulary for deep structure.
6The one honest limit is human. Nine levels is almost always a sign the document wants components instead, which is why the Library exists: a nested tree you reuse is a component, not a deeper group.
06

Groups inside groups

Nesting is unbounded, and it costs nothing to support because it is not a feature: it falls out of "a group is a layer". The pane renders depth, the commands ignore it, and the composite walks it.

What is bounded is the indent, which is presentation. It caps so that a deep tree keeps showing names rather than whitespace, and the row says its own depth once the indent stops saying it.

Let a group hold groups, to any depth. Cap the model to keep the indentation tidy.

07

Rearranging

Order in the pane is composite order, so a drag here is a real edit to the document and goes through history like any other. The pane must therefore be honest about where a drop will land before you release, which is what the indented drop line is for.

Indent the drop line to the parent it lands in. Draw one flat line and let people find out on release.

Toolbar component
Screenshot

A collapsed group whose subtree contains the selection carries a dot. Without it, a canvas selection can vanish from the pane entirely and the pane starts lying about the current state.

What collapsing does and does not do
Click ▸Toggle one group.
⌥ Click ▸Toggle the group and its whole subtree.
← →Collapse or expand the selected group; ← on a leaf jumps to its parent.
⌥ ⌘ ←Collapse every group in the document to the top level.

Collapse state saves with the document, not with the app, because it is a note about this drawing: the parts you are done with are folded. Reopen the file a week later and the structure is folded exactly the way you left it, on any machine.

It is never an edit. Collapsing does not change the composite, does not enter history, and cannot be undone with ⌘Z, because an undo that folded a group instead of reverting your last real change would be worse than useless.

Two rules keep the tree from fighting you. The pane auto-expands the path to a layer the moment it becomes selected somewhere else, so selecting on the canvas always reveals the row. And it never auto-collapses anything on its own: the tree only folds when you fold it, so a structure you opened on purpose stays open.

Hidden rows dim their whole content, not just the glyph, so the state reads from across the room. A locked row keeps full contrast: it is present and composited, just not clickable, and dimming it would say the opposite.

The gestures
Click the eyeHide or show that layer.
⌥ Click the eyeSolo: hide everything else. Again to restore exactly what was hidden before.
Drag down the eyesToggle a whole run in one stroke, all rows matching the first one you flipped.
⇧⌘,Hide or show the selection, wherever the pane is scrolled.
Click the lockLock: unclickable on canvas, still selectable here.
⌥ Click the lockUnlock everything in the document.

Hiding a group hides its children without changing their own eyes, so unhiding the group brings back exactly the mix you had. A child that was already hidden stays hidden.

Both are document state and both are undoable, because hiding a layer changes what exports. They are the only two row controls that are not a property edit, which is why they get a permanent slot in the row instead of living in Properties with everything else.

10

When the list gets long

Sixty rows in a 180px budget
It scrolls, it does not spread

The pane has a height budget and its own scroller, so a long document scrolls inside Layers and never pushes Properties or Effects off the screen. Drag the divider below it to trade height with the pane underneath when you genuinely need more.

Find filters the tree

Typing in Find keeps matching rows and their parents, so a result never appears without the structure that explains where it is. Clearing the field restores your previous scroll position and your previous collapse state, both untouched.

Grouping is the real answer

A sixty-row flat list is a structural problem, not a scrolling one. The pane makes grouping cheap on purpose: ⌘G, type a name, done. Every affordance here is designed to make that the path of least resistance.

11

Rules

Do and don't
Keep one tree that mirrors composite order. Add a second list, a tab, or a separate object browser. Reveal the selected row automatically, from any source. Let a canvas selection leave the pane scrolled elsewhere. Indent the drop line to show the parent it lands in. Draw one flat line and reveal the parent only on release. Save collapse state with the document. Put collapse in history, or let ⌘Z unfold a group. Give every row the same six slots, always in the same order. Reflow a row because one of its slots happens to be empty. Make grouping cheap: one shortcut, then the name. Make a group a folder that cannot carry opacity or effects.
12

In the API

Every row, every gesture, one call
CallWhat it does
doc.layersThe tree itself, in composite order, nested. Reading it is reading the document.
select(["step-1", "arrow"])Set the selection. Rings the canvas, highlights the rows, reveals them, and repopulates Properties, all from one call.
selection.group("Callouts")What ⌘G does, including the name, so an agent never has to leave a group called "Group 4".
selection.ungroup()Push the group's own opacity and effects down onto the children, then dissolve it.
layer.move(to:index:)Reparent and reorder in one step. The same call a drop makes, and the same single undo entry.
layer.visible = falseThe eye. Undoable, because it changes what exports.
layer.locked = trueThe lock. Unclickable on canvas, still reachable in the pane.
layer.expanded = trueThe disclosure. Saved with the document and deliberately outside history.
pane("layers").find = "arrow"The Find field, so "show me every arrow" is the same filter you would have typed.

"Group all the callouts and drop a shadow on the group" is four of these calls in a row, issued by an agent, and each one lands in history exactly as if you had done it by hand. That is the test for whether the pane is designed properly: every gesture in it has a name.

The idea

The Layers pane is the document with a handle on it. Because every kind of content is the same kind of row, the pane you learn on a screenshot is the pane you already know on a video or a UI mockup, and a new capability arrives as a new row type rather than a new surface to learn.

A direction

Colour tags on rows, set from the row's context menu and filterable from Find. In a long redline document the useful grouping is often "everything I still have to fix", which cuts across the structural groups and has nowhere to live today.

Open question

Should the pane show a thumbnail per row? It helps enormously on a photo composite and is close to noise on forty annotation shapes. The likely answer is a density control on the pane menu rather than a fixed choice, but a setting is also an admission that we did not decide.
