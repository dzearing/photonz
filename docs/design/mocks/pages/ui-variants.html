The idea

A component exposes variants (its named forms) and properties (the knobs on one instance). The canvas is the live sheet for both: the matrix shows every Button variant across every size, and the Properties group edits a real instance so the preview updates as you type.

A direction

Because props are just data, the panel and the API are the same surface. Set showIcon, retype the label, or swap the icon and it is one call either way. See it in the library

Open question

Should a variant be a fixed enum on the main, or should any saved property set be promotable to a named variant later, so a one-off instance can graduate into the sheet without a round trip through the design system?
