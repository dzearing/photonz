The idea

A design system is not its own window. Tokens are a panel group, Styles and Components are scopes of the same Library group, and picking one drives the specimen on the canvas and the Properties group, exactly like picking a layer.

Direction

Tokens → Styles → Components → Systems is one ladder. A whole system is browsable in a slide-down overlay rather than a permanent column, so applying Brand v2 or a system the agent extracted from a URL is one click away without costing canvas width.

Open question

Should Tokens stay its own group, or become a fifth Library scope so there is exactly one reuse surface? And when an imported system and a local override disagree, which wins by default?

Fonts are tokens too

Each typeface is a semantic name mapped to a resolved family: Display → New York, Text → SF Pro, Mono → SF Mono. Rename or add your own, like a custom Brand.

The whole system is data

Tokens, typefaces, styles and components bundle with a name and a version, export to .json or .photonz-ds, and round-trip between people and projects. Ship it like a package and a team applies Brand v2 in one call.

API mirror

font("Display") resolves through the system · text(face:"Display") stays stable when the family changes · system.apply("Brand v2") re-themes every instance.
