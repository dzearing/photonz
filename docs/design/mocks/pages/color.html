Color

· the picking primitive · one popover, every slot

A color is picked one way in this app. Click a swatch, anywhere, and the same popover opens: a saturation field, a hue track, hex or RGB or HSL typed straight in, and a row of shades derived from the color you are already on so "a bit darker" costs one click instead of a second dialog. There is no second color UI, no slot that quietly hands you the system color panel, and no place where the swatch is not the thing you click.

One popover, five triggers

The Fill, Stroke, Text and Shadow rows and the tool bar's foreground swatch all open the same picker. It re-anchors to the swatch you clicked and keeps its recents and its shades, so moving between slots never resets what you were working from.

Try it

Drag inside the field, drag the hue track, or switch to RGB or HSL and type. The hex field also accepts a pasted rgb(124, 77, 255) or hsl(258 100% 65%), because paste is how a color usually arrives.

API mirror

layer.fill = color("#7C4DFF") · color.shade(-2) for one step darker · color.style("Brand/500") once it has a name.

Eight places you can set a color, one control that sets it. The trigger is always a swatch with its hex beside it, never a labelled button, never a color well that opens something else. If you can see the swatch you already know what clicking it does.

A shade holds the hue and the saturation and moves only the lightness, so a ramp reads as one color family instead of drifting toward gray or toward a different hue. The ring marks where your current color sits, which also tells you how much darker you can still go before you run out.

The rules that make it consistent (each one is a thing that is wrong today)
A swatch is the only trigger. Every color in the app is set by clicking a swatch that shows the current color. No color wells, no "Choose..." buttons, no double-click-to-discover. The same popover opens every time. No slot falls through to the system color panel, so the layout, the shortcuts and the recents never change under you. The canvas updates while you drag, undo does not. The whole visit to the picker is one undo step, so ⌘Z takes you back to the color you had, not to the middle of a drag. Recents are one list, app-wide. A color used on an annotation is offered on a fill, in every window, because it is your palette and not the popover's. Type anything, get a color. Hex with or without the hash, three digits or six, rgb(), hsl(), with an alpha or without. Opacity appears only where it applies. A slot that cannot be transparent does not show a track that does nothing. Escape cancels, outside-click commits. Escape puts back the color you opened on, which is why the before swatch stays visible the whole time. The eyedropper is always in the same corner. Sampling is part of picking, not a separate tool you have to go find.
The idea

Color picking is a primitive, not a feature of the inspector. One popover, one trigger grammar, one recents list, and a derived shades row so the common edit, slightly lighter or slightly darker, never requires reading a number.

A direction

Let the shades row snap to the design system when one is loaded, so the nine steps become brand/100 through brand/900 and picking a shade picks a token instead of a hex. The picker would then teach the palette rather than compete with it.

Open question

Should the field be HSV, which is what the square really is, or should it show HSL to match what people type? They disagree at the top edge, and pretending otherwise is how a picker starts feeling untrustworthy.
