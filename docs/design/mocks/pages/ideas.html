UI design3 ideas

Brand kit import

M

Paste a Figma file or a live site URL and pull its color, type, spacing and radius into your library as real Styles you can paint with.

Why it fits: an importer just emits create_style calls, so it populates the Tokens and Styles tiers through the same API the UI uses.

Smart guides and auto-layout

M

Stacks and grids that reflow when content changes, with live gap and edge readouts as you nudge, so spacing is never a guess.

Why it fits: layout is a Layer property in the model, so the same measured gaps power redlining and the assistant can set them too.

Data-bound components

M

Point a component at a table or JSON and it repeats once per row, re-painting each instance from the data. Feed a list, get a list.

Why it fits: a Component is an instanceable layer tree, so binding is one instance command per row over the API.
Image3 ideas

Generative fill and erase

M

Select, then remove a distraction, extend a background, or heal a blemish. Magic eraser, background remove and outpaint as one family of moves.

Why it fits: each is a non-destructive adjustment Layer driven by the model-agnostic command surface, local by default.

Contrast and a11y checker

S

Live WCAG contrast on any text-on-fill pair, with a one-tap fix that shifts the Paint to the nearest passing shade.

Why it fits: contrast is computed straight from the Type and Paint primitives, so the number is exact and the fix is a Paint edit.

Agent alt text and naming

S

Auto-name messy layers and write alt text from what each layer actually contains, so files stay tidy and exports stay accessible.

Why it fits: the local model reads the layer tree and writes back through rename and metadata commands. Nothing leaves the machine.
Video2 ideas

Screen record to component

L

Record a UI region and drop it on the timeline as a keyframed lower-third or callout that you can re-paint and re-time later.

Why it fits: a Component is just a layer tree, so the same one lands on a canvas, a photo, or a video track unchanged.

Motion presets and easing

M

Named entrances, emphasis and easing curves you save once and reuse across every clip. Edit the curve, every use updates.

Why it fits: motion is the Styles tier extended to keyframes, so an easing curve is a reusable, API-addressable Style.
Cross-cutting2 ideas

Version history and branches

M

Scrub a visual timeline of the document, name a moment, or branch to explore a variant without forking a copy of the file.

Why it fits: the model is value-typed and Codable and every edit runs through History, so snapshots and branches are cheap by construction.

Export presets

S

Save a recipe once (2x PNG, sRGB, padded, copied to clipboard) and re-run it on any selection with a single keystroke.

Why it fits: export is one command, so a preset is just saved arguments. Great for redliners shipping the same crop all day.
Automation2 ideas

Plugin and extension API

L

Third-party tools and panels built on the same commands the app calls, so a plugin is a first-class citizen, not a bolt-on.

Why it fits: every UI action is one API call already, so plugins and the MCP server drive the exact same validated command surface.

Action recorder

M

Record a sequence of edits once and replay it as a named action across a folder of shots. Photoshop Actions, but readable and safe.

Why it fits: commands are serializable and undoable, so a recording is a saved script that any model or batch job can re-run.
The through-line

Not one of these is a new engine. Each is a thin surface over the same five primitives and the command API, which is exactly what keeps creation consistent instead of sprawling.

How we would prioritize

Ship the small wins that ride existing primitives first (export presets, contrast, alt-text), then the medium reuse plays (brand kit, data-bound, actions). Large bets like the plugin API wait until the primitives freeze.

Open question

Interactive prototypes and live multiplayer are the two we deliberately left off. Both are real power-user wants, but do they earn their weight before image creation and the API are proven end to end?
