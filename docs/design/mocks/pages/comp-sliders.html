Sliders & value controls

· Component library Component library

One slider: a capsule thumb on a thick groove, the platform's shape at inspector density. On top of that, the variants a photo editor actually needs — a fill that grows from the centre for signed adjustments, a paint track for hue and alpha, a two-value range, and ticks for stepped values. Every one of them keeps the same thumb, so a panel full of different sliders still reads as one control repeated.

01

Anatomy

Six parts, and the row is part of the component rather than something each panel re-authors. Under the visual layer there is a real range input, transparent and full-bleed, so arrow keys, page keys, Home/End and VoiceOver all work without a line of extra code, and there is exactly one tab stop.

Give every slider a numeric readout. A slider alone is not precise. Show the bubble at rest. It covers the row above it.

API layer.opacity = .62. The drag issues one command on release, not sixty during the drag, so undo takes you back to where you started.

Neutral 20 × 14, light in both themes

Sets a number. The thumb stays uncoloured and the fill carries the accent, so the eye reads the amount from the track rather than the knob.

Carrying a hue .paint.hue

Same capsule, filled with the colour it is currently on, keylined in white so it stays readable anywhere along the ramp. There is no fill, because the groove already is the value.

Carrying transparency .paint.alpha

The thumb sits on the same checkerboard as the track, so a half-transparent colour looks half transparent in the knob you are dragging, not only in the ramp behind it.

02

One thumb, three jobs

The capsule never changes shape; only what is inside it does. When a slider sets a number the thumb stays neutral and the fill carries the meaning. When it sets a colour the thumb carries the meaning and the fill goes away. That swap is what lets a hue ramp and an opacity row sit in the same panel and still read as siblings.

Show alpha on the thumb, over the same checkerboard as the track. Tint a neutral thumb with the accent. The fill already says it.

API geometry is tokenised: --sl-thumb-w / --sl-track / --sl-c, so a density or colour change is one edit rather than forty.

Exposure+1.4 EV Temperature-32 Bipolar .bipolar

The fill grows out of the centre. Every signed adjustment is bipolar: a left-origin fill on a -100..100 control shows "half full" at zero, which is a lie.

The groove is the value, so there is no fill. The thumb carries the current colour with a white keyline, so it stays visible over any part of the ramp.

Two thumbs, fill between. Pointer-down grabs the nearer one, which is the only rule that feels right when the two sit close together.

A stepped control shows where it will land. The small size is for toolbars and dense rows; it keeps the same capsule, 16 × 11.

03

Variants

Four, each solving a problem the plain slider gets wrong rather than adding decoration. Bipolar for signed values, paint where the track carries the meaning, range for two ends of one thing, ticks where the value is discrete.

Use bipolar for anything that can be negative. It is not optional. Put a continuous slider on a value that only takes 4 settings.

API the variant is derived from the property's schema (range, signed, step, unit), so a new adjustment gets the right slider without anyone choosing.

04

States

The ends are the state everyone gets wrong. At 0 and at 100 the thumb must sit fully inside the groove, not half off the end, which means the travel is inset by half a thumb and the fill has to use the same inset. Both come from one expression here, so they cannot disagree.

Ring the thumb on focus, then drive it with arrow keys. Let the thumb overhang the track at 0. It looks broken, and it is.

API --p is the only thing the visual layer reads; keyboard, pointer and a command all move the same value through the same input.

Dial .dial

Angle only: rotation, a gradient's direction, a light source. Anything circular by nature, where a straight track would need a wrap-around.

0:14 1:00 Scrubber .scrub

Time, not a value. Same capsule playhead at the large size, plus marks for cuts and keyframes that a slider has no concept of.

Gradient ramp .gramp

Many values on one track. The stops are square, not capsules, because they are objects you can select and delete, not a knob you drag along.

05

The rest of the family

Three relatives that look like sliders and are not. The rule for telling them apart: a slider has one value on a bounded scale. A dial is angular, a scrubber is a position in time with marks on it, and a ramp holds a list of objects.

Use a dial only for angles. Everything else is a slider. Add marks to a slider. Marks mean it is a timeline.

API node.rotation = 42 · player.time = 14.2 · paint.stops[1].at = .46. Three shapes of data, three controls.

Reduced motion drops the thumb's grow and the fill's ease; the value still updates live, since that is information, not decoration.

The idea

A slider is coarse by nature, so it never ships alone. The pairing that makes it professional is track for the gesture, number for the precision, and the number is draggable too, so you never have to switch tools to get the last two percent.

A direction

Holding a modifier while dragging could shrink the travel to a tenth of its range around the current value, so one gesture goes from coarse to fine without letting go. That is the behaviour people expect from a pro tool and it costs one line of hit-testing.

Open question

SwiftUI's Slider gives us none of this: no bipolar fill, no paint track, no bubble, no scrub label. Do we wrap NSSlider and fight its cell drawing, or draw the whole control ourselves and accept owning the accessibility work?
