Documents

· how a file persists, and the edit loop that changes it

A document is a plain .phz file holding layers, Styles and effects as data, never baked pixels. Two things make it feel safe: you can always tell whether it is saved, and you can always get back to a version you liked. Both live in the same shell as everything else, with Versions as one more panel group in the one right dock.

Saving, made legible

A dot on the title reads Edited the moment you change something and clears to Saved on ⌘S. Autosave keeps a running copy, so "saved a moment ago" is always true. An explicit Save just pins a named point you can return to.

Portable by design

The document is a plain .phz file: layers, Styles and effects as data, never baked pixels. It round-trips the same way the design system does, so a file opened anywhere rebuilds identically.

Versions are a panel group

Version history did not need a new sidebar or a new window. It is a Versions group in the one dock, so it collapses, resizes and scrolls like Layers does.

One loop, everywhere

Select puts a ring on an object and highlights its row in Layers, Inspect fills the Properties group with its real values, and Change updates the canvas the instant you edit one. The same three steps drive a shape, a photo layer, or a component instance.

Non-destructive

Corner radius, fill, opacity, effects and adjustments are stored as re-editable settings, never flattened. The original is always intact, so any value can be dialed back later or undone step by step.

Open question

Undo history is per document today. Should named checkpoints, like the version snapshots above, and step-level undo be the same timeline, or stay two layers a power user switches between?
