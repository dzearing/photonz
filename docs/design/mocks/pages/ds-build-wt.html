The idea

A system is named work you already did. Nothing here is a separate mode: the same canvas, the same Layers, the same Properties, the same Library panel. Tokens become Styles, a layer group becomes a Component, and the pair becomes a published System.

A direction

The Systems scope could also be where you consume a system: browse a catalog, or run system.extract(url) to infer tokens from a website, then apply it and watch every component re-resolve.

Open question

Every step here is one API call, so an agent can build the same system. When a published system and a local override disagree, which should win by default, and can that be pinned per token?
