The idea

A design system is just data. Pick a different one and the whole document re-paints against it live: accent, typeface, and radius all change at once, with a smooth transition, no re-layout.

A direction

Keep several systems side by side and flip between them to compare a real screen under each, the way you would preview a theme. The active one is marked, so it reads like choosing an appearance.

Open question

When a layer carries a local override that disagrees with the applied system, does the system win or the override? Should re-theme respect pinned values per layer?

The idea

Because a system is portable data, a whole team can share one file and every document that adopts it stays on brand. Applying Acme Team is a single choice.

A direction

Treat systems like appearances you can flip between, or ship as versioned packages. A newer version reads as a real changelog against the one you are on.

Open question

If two systems name the same token but mean different things, how do we warn before applying, and can a document map one system's names onto another on import?
