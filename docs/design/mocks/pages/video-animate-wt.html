The idea

Animation is not a mode and not a second window. Time is a property of the document, so the transport and timeline are already there, and a keyframe is just a value recorded at a moment. The button that makes one sits on the same Properties row as the value it records.

A direction

The timeline could become a fourth panel group docked to the bottom, so a long multi-track edit collapses, resizes, and scrolls with the same vocabulary as Layers and Library. Keyframe lanes would then be a group inside it.

Open question

Every step is one API call (layer.key("opacity"), key.ease("inOut"), style.apply("Pop in")), so an agent can animate too. Should easing live per segment only, or should a property carry a default curve you override at single keys?
