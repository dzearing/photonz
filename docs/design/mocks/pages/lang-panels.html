Panels & the dock

· Design language Design language

There is one dock, on the right, and it holds stacked panel groups: Layers, Properties, Effects, Library. There is no left dock, no floating panel, and no tearing off. Every group is independently collapsible and independently scrollable inside its own bounded height. The dock resizes by dragging a splitter and collapses entirely to a labeled rail. That small vocabulary is what lets the app grow into UI design, components and richer video without becoming a different app: new capability is a new group, never new chrome.

Click the header to collapse. Scroll inside the body. Both are the shared behaviour, not page code.

1Chevron · the disclosure affordance. It is injected, so every group gets one and they all rotate the same way. .chev
2Title · the group's name, one word where possible. The whole header is the hit target, not just the chevron. .ttl
3Count or summary · how many items, or what the group currently resolves to, so a collapsed group still answers a question. .cnt
4Header buttons · add and panel-menu actions scoped to this group. Always .btn.ghost.icon.sm, never a bespoke square.
5Body · the content, with its own bounded height (--gh) and its own scroller. This is the rule that makes the dock scale. .dgrp-b
·Grow · exactly one group per dock may be .grow and take the leftover space instead of a fixed bound.

The bounded body is the whole trick. A sixty-layer document scrolls inside Layers. It never pushes Effects or Library off the bottom of the dock, and it never stretches the window. That is why adding a panel group is cheap: the dock's shape does not change when scope grows, only the number of groups in it. Give the window a definite height and put every long list in a .dgrp-b, and the layout takes care of itself.

1Dock · one persistent column on the right. It never moves to another edge and it never becomes two columns. .pdock
2Stacked groups · in a fixed order: Layers, Properties, Effects, Library. Order is the same in every workspace so muscle memory holds.
3Horizontal splitter · drag to resize the group above it, bounded by data-min and data-max, keyboard-resizable. .splitter.h
4Vertical splitter · the dock's own width, dragged from the canvas edge. Sizes persist for the session. .splitter.v
5Grow group · one group takes the leftover height. Library is usually the one, because browsing wants room. .dgrp.grow
6Rail · what the whole dock collapses to. A tab restores the dock and reveals that group. .drail › .drailtab
·Library is a group, not a surface of its own: one Library with a scope switch for Media · Components · Styles · Assets. The video "media pool" is this group with scope set to Media.

A feature that seems to need chrome outside dock, group, splitter, rail, floating tool bar, transport bar and overlay is a signal to adjust the foundation, not to invent locally. One place, one shape, one thing to learn.

07

Rules

Do / Don't
Put every long list in a .dgrp-b with its own bound and scroller. Let a list stretch the window instead of scrolling inside its group. Add a new group when scope grows. The dock's shape never changes. Invent a second dock, a left dock, or a bespoke panel for one feature. Keep the group order the same in every workspace. Tear a panel off into a floating window. Nothing floats except overlays and the tool bar. Give exactly one group .grow, and let the rest carry a bound. Promote a Library scope to its own panel. One Library, four scopes. Keep the panel toggle on the canvas, where the space is being spent. Drop the group header when the dock rails. The rail is labeled for a reason.
08

In the API

Every layout move is one command
panel.dock("right")The dock's state: open, closed (railed), or overlay (narrow).
group("Layers").collapsed = trueCollapse one group to its header. The count or summary stays readable.
group("Library").reveal()What a rail tab does: restore the dock and scroll that group into view.
group("Layers").height = 240What dragging a horizontal splitter does. Bounded by the group's min and max.
dock.width = 300What dragging the vertical splitter does. Sizes persist for the session.
library.scope = "media"The Library scope switch: media, components, styles, assets.

A layout you can build by hand an agent can build for you, because it is the same set of calls. See the dock in the whole shell in App shell, or working in the editor.

The idea

One dock, stacked groups, and three moves: collapse, resize, scroll. Learn them once and every panel in the app behaves the same, whether you are grading a photo, laying out a screen, or cutting a video.

A direction

Because the layout is just commands, a workspace preset could ship per task: Retouch, Compose, Cut. Switching one runs a handful of collapse and resize calls, and a single reset layout puts everything back.

Open question

The dock remembers one layout per document today. Should a workspace lens carry its own dock layout, so switching to Video restores the panel set you last used there, or does that break the promise that a lens only re-arranges chrome around the same document?
